# Commandes par sujet

> Les commandes et workflows qui ne servent qu’à un sujet : captures, bannière, winget, annonce Discord, aperçu Linux, contrôles Windows en CI, fluidité, audit de l’interface, budgets, Defender, publication. Build, tests et CI de tous les jours : `CLAUDE.md`.

- Captures du README (`docs/screenshots/readme/`) : `gallery.yml` à la demande (`actions_run_trigger` sur une branche : JPEG poussés sur elle ; jamais sur PR, son propre commit la relancerait) ; Windows : Jellyfin 12.1 compilé depuis ses sources, `Mira.exe --data <p> --readme-gallery <dossier>` (vraie fenêtre connectée, ×2) ; iPhone (job `iphone`, macos-26) : le même Jellyfin 12.1 compilé sur le Mac (ffmpeg de Homebrew), l'app sur le simulateur iPhone 17 Pro (1206 × 2622) par `testGallery` de `MiraUITests` (sauté sans `MIRA_GALLERY_SERVER`, donc par `ios.yml`), captures `iphone-home`, `-movies`, `-film`, `-together`, `-series` (aperçus `MIRA-PREVIEW` dans le journal) ; le site en tire ses images (`tools/site/images.py`) ; bibliothèque de démonstration de `tools/banner/media.sh` (42 films, 11 séries depuis le 2026-11-15 : Ghibli, animé, néo-noir, SF, Tarantino, goûts d’ogsas ; Howl’s Moving Castle repris sur les trois apps (`GALLERY_FILM`), lecteur et mini-lecteur des bannières sur Blade Runner 2049 (`GALLERY_PLAYING`) ; aucune taille de fichier sur les pages (`TitleStorage.Shown`, iPhone `-mira-no-sizes`) ; un nom qui ne trouve pas le bon titre sur TMDb (Nausicaä = « Warriors of the Wind » en anglais) : le remplacer ; vidéos noires nommées pour TMDb, passages dans `tools/banner/traces.json`, comme les bannières), `GALLERY_LANGUAGE`/`language` = `en` par défaut (`fr` pour `docs/README.fr.md`), affiches de TMDb (inaccessible depuis le conteneur cloud) ; Mac : `mac-film`, `mac-filters` tirés de `Mira --gallery` (Avalonia sous Xvfb, comme les bannières), `windows-player` d'une prise des bannières (`MIRA_GALLERY_BANNER`) : pas refaits par le mode README, à reprendre à la main (`ffmpeg -q:v 3`) ; en-tête `header.jpg`/`header-fr.jpg` (mur d'affiches comme le site « Le vidéoclub », sans Arcane) par `PLAYWRIGHT=… node tools/readme/header.mjs <dossier des poster-*.jpg> <out.jpg> [en|fr]` (2026-11-15).
- Bannière de release (`tools/banner/`, `docs/releases/x.y.z.jpg`) : UNE BANNIÈRE PROPRE À CHAQUE RELEASE (ogsas, 2026-11-14 : la première de la 0.9.9 reprenait la fiche d'Arcane de la 0.9.8, tailles des vidéos factices comprises) : chaque morceau montre un point de cette version (`point` ou `caption`), aucun ne recoupe de plus de moitié un morceau de la même capture dans la release d'avant, pas deux fois sans bande (`plan.mjs`, refusé dès le job `plan` de `banner.yml`) ; la dernière version de `WhatsNew.json` doit avoir son entrée et celle d'avant la garder (`plan.test.mjs`, job `portable`) ; `release.ps1` s'arrête sans `docs/releases/x.y.z.jpg` ou si c'est le fichier de la version d'avant (`-NoBanner` : sans) ; vidéos de la bibliothèque des bannières = petits fichiers noirs : jamais un morceau qui montre des tailles de fichier (fiche, épisodes). Sur la branche de préparation, une entrée de `tools/banner/scenes.json` (format en tête de `plan.mjs`) : « Gros plan » (`closeup`, x.y.z avec z > 0, choisi par ogsas le 2026-11-15, maquettes `/mnt/project-files/banniere-release/propositions-2026-11-15/`) = `{ film, point, shot, at, size, scale }` : une nouveauté, une seule chose de l'app entière à droite (`size` en unités de l'app, 636 × 500 px de bannière au plus, `scale` 0,45 à 1,5, centrée entre x = 500 et 1136 ou `right`), éclairée par la lueur floue du fond de `film` (un titre de `tools/banner/media.sh` par le nom de son dossier : `howl-s-moving-castle` ; sinon FNV-1a, jamais celui d'avant ni `spirited-away`), titre = `en.title` du point (`title` à la main), texte = son `en.text` (`say` à la main, 4 lignes au plus), « Also » = les autres titres (`also`, coupé à droite faute de place) ; sans `shot` = l'Accueil de Windows entier ; jamais la même chose (recoupée à plus de moitié), l'Accueil ni le film deux fois de suite. `film` (bande de morceaux légendés, `band`) reste pour les entrées 0.9.5 à 0.9.12 seulement, puis `banner.yml` (`actions_run_trigger`, entrée `version`, ~35 min avec Windows) : `plan.mjs` dit le modèle (`closeup` pour x.y.z avec z > 0 ; `lineup` pour x.y.0 : Windows, Mac et iPhone devant un film, réglé par `lineup: { lead, back, phone, focus }` ; `template` pour forcer) et les captures utiles ; refus clairs dans `plan.mjs` (tests `node --test tools/banner/plan.test.mjs`, job `portable`), puis au dessin avec les vraies tailles (`closeup` : titre en 3 lignes au plus, texte en 4, « Also » à l'écart de la chose, chose hors de sa capture) ; Windows et iPhone = jobs de `gallery.yml` appelés (`windows_only`, `iphone_only`), Mac = `Mira --gallery <dossier>` (Avalonia sous `xvfb-run`, `AVALONIA_GLOBAL_SCALE_FACTOR=2`, feux dessinés par la bannière quand un morceau part de [0, 0], pas d'image mpv sous Linux) ; prises propres aux bannières (`SHOTS` de `plan.mjs`) : `windows-filters`/`mac-filters` (panneau Filtrer ouvert), `windows-missing`/`mac-missing` (épisodes manquants d'Invincible à leur place, par `tools/web/fake-tvdb` dans les extensions du Jellyfin de `banner.yml` et de `gallery.yml` avec `windows_only`), `windows-mini` (mini-lecteur sorti sur l'Accueil, commandes montrées : libmpv par `tools/mpv-engine.ps1` dans le profil, vidéo de Spider-Verse refaite de son fond par ffmpeg, image de mpv (`screenshot-to-file`) posée dans la capture par `CaptureWithVideoAsync`) ; `MIRA_GALLERY_BANNER=1` les demande à `--readme-gallery`, jamais pour le README, fonds `still-<titre>.jpg` de chaque titre par `tools/banner/stills.mjs` (API de Jellyfin) ; commit sur la branche par `GITHUB_TOKEN` (qui ne relance pas la CI : la lancer avant le dernier commit de la PR). `release.ps1` la met en tête des notes (`notes --banner`, image servie depuis le tag), sinon avertit. Locale : `PLAYWRIGHT=… node tools/banner/banner.mjs <x.y.z> <captures> <out.jpg> [closeup|film|lineup]` (captures 0.9.12 et fonds `backdrop-*` à renommer `still-*` : `/mnt/project-files/captures-2026-11-15/`).
- winget (2026-11-07, piste 14 de l'audit) : `winget.yml` à chaque release publiée (et `workflow_dispatch`, entrées `version`, `submit` ; sur PR qui touche `tools/winget`, le workflow ou `Mira.iss` : sans soumission) : manifestes `sasou-web.Mira` (schéma 1.10.0 : le winget 1.11 des runners refuse 1.12 d’un avertissement, version + installateur Inno `Scope: user` + en-US + fr-FR, notes de `WhatsNew.json` au tag, code produit = `AppId` de `Mira.iss` + `_is1`) par `node tools/winget/manifests.mjs <x.y.z> <sha256> <date> <dossier>` (tests `manifests.test.mjs`), installateur vérifié trois fois (octets, `.sha256`, digest GitHub), puis sur Windows `winget validate`, vraie installation et désinstallation depuis les manifestes, puis `wingetcreate submit` (1.12.13.0, SHA-256 épinglé + signature Microsoft) vers microsoft/winget-pkgs ; secret `WINGET_TOKEN` (jeton classique de sasou-web, `public_repo` ; absent = rien de soumis) ; version déjà dans winget-pkgs = rien ; tant que Mira n'y est pas et qu'une PR `sasou-web.Mira` attend un modérateur, rien de soumis (sinon une PR « New package » de plus par release : 0.9.5 à 0.9.7, 2026-11-13). winget-pkgs n'exige aucune signature, mais tout installateur signalé par un antivirus de sa validation est refusé (faux positif = https://www.microsoft.com/wdsi/filesubmission puis `@wingetbot run` par un modérateur) ; CLA de Microsoft à accepter par sasou-web à la première PR. Runner : winget 1.11 (schéma 1.12 = avertissement, code 0x8A150028), installateur marqué « Internet » par winget = invite « Avertissement de sécurité » invisible qui bloque Setup sans fin (`LowRiskFileTypes` `.exe` dans le job), `--accept-source-agreements` aussi pour `uninstall` (msstore).

- Aperçu Linux de l'app Mac (2026-11-09, point 11a d'`ameliorations-2026-11-09.md`, pour qu'ogsas l'essaie ; pas une Mira pour Linux, jamais jointe à une release) : `tools/linux/package.sh <x.y.z>` → `dist/linux/Mira-x.y.z-linux-x64-preview.tar.gz` (publish autonome linux-x64, `mira-tailscale` linux/amd64, lanceur `mira` qui trouve `libmpv.so.2` du système par `ldconfig` → `MIRA_LIBMPV`, `README.txt`) ; `linux.yml` (push sur `main`, `workflow_dispatch`) le fait ; sous WSL (ogsas n'a pas de Linux) le lanceur pose l'échelle 2 (`AVALONIA_GLOBAL_SCALE_FACTOR`, WSL dit 1) et demande les bibliothèques X11 absentes de son Ubuntu ; défilement sous WSL non représentatif, le lance sous Xvfb comme une personne (vivant à 30 s, fenêtre dessinée), artefact `Mira-linux-preview` (30 jours). Profil `~/.local/share/Mira`, session en `session.json` 0600, mises à jour = simple avis.
- Vrai lecteur Windows en CI : `tools/player-check.ps1` (dans `ci.yml`) : libmpv de `MpvPackage.Current` (SourceForge, archive gardée par `actions/cache`), clip de 18 s à chapitres par l'ffmpeg d'`imageio-ffmpeg` (PyPI, `--require-hashes` ; pas d'ffmpeg sur les runners Windows), puis `Mira.exe --player-check` ; écran du runner 1024 × 768 : plein écran de contrôle ramené au moniteur (`CheckScreen`). Captures lisibles par `previews` (`player-window-capture`, `player-bar`, `mini-player`, `player-play-state` = l'indicateur lecture/pause sur l'image ; `preview_quality` 90 pour regarder de près, 50 par défaut). `--perf-probe` ajoute images par seconde et lecture des propriétés de mpv (lignes INFO) ; puis `tools/idle-check.ps1` : Accueil de la démo au repos 60 s (part d'un cœur, Mo privés, octets écrits) dans le résumé du job, tenu aux budgets (2026-10-28 : 0,08 %, 80 Mo, 0 octet).
- Mira pour Windows contre un vrai Jellyfin en CI : job `server` de `ci.yml`, `tools/server-check.ps1 -Jellyfin <dossier de jellyfin.dll>` (Jellyfin 12.1 compilé depuis ses sources, en cache ; médias de `tools/web/media.sh` + « Coupure Test », 4 min à 4 Mb/s ; `setup.mjs` ; libmpv par `tools/mpv-engine.ps1`, commun avec `player-check.ps1`) puis `Mira.exe --server-check` à l'adresse réseau du runner (à `127.0.0.1`, Mira lit le fichier lui-même) ; `MIRA_STOP`/`MIRA_START` = lignes de `cmd.exe /s /c`. Second appareil de « Regarder ensemble » = `Friend` du contrôle (même compte, autre `DeviceId`). Puis, avec `-Testnet <mira-testnet.exe>`, `Mira.exe --tailnet-check` deux fois (`--tailnet-control http://127.0.0.1:18090` ; le « PC de Jellyfin » de mira-testnet transfère 8096 au Jellyfin du job) : Tailscale intégré de la carte de connexion à la déconnexion.
- Fluidité des pages : Windows `tools/smooth-check.ps1 [-Placement edge|offscreen]` (`Mira.exe --data <p> --smooth-check <dossier>`, job `smooth` de `ci.yml`), Mac `Mira --data <p> --smooth-check <dossier>` (étape de `mac.yml` ; sous Linux par `xvfb-run -a -s "-screen 0 1920x1200x24"`, `libmpv2` d'apt) : Mira connecté à `StandInJellyfin` (Jellyfin répondu dans Mira : 240 films, 36 séries, JPEG, délai d'une maison ; partagé avec le Mac par lien, images par Skia, tampons de `ArrayPool` : ses propres allocations faisaient les GC qu'il mesurait), défilement, pages du rail (1re fois, puis de nouveau), fiche, Réglages, image par image (`report.txt`/`.json`, `summary.md`, clic = temps tenu sur le fil de l'interface) ; budgets ci-dessous, un runner compare deux commits ; sur le PC d'ogsas par Remote Control, fenêtre jamais au premier plan (`edge`), profil à part.
- Audit de l’interface (2026-11-14, demandé par ogsas : les petits défauts qu’il remontait à la main) : `tools/ui-audit.ps1` (`Mira.exe --data <p> --ui-audit <dossier> --language fr|en`, `Checks/MainWindow.UiAudit.cs` + `UiInspector.cs` + `UiAuditReport.cs`) : Mira connecté à un vrai Jellyfin avec la session copiée d’un Mira installé (`session.protected` + `device-id`, même compte, même appareil pour Jellyfin, jamais un nouveau login), parcourt Accueil, bibliothèques, filtres et listes, fiches (menus ouverts, jamais choisis ; « Get season » dessiné sans recherche : `OpenMissingMenu` sous `MIRA_VALIDATION`), Réglages, Guide, Téléchargements à 3 tailles ; mesures dans l’arbre WPF (bords d’un défilement = atteignables, ceux d’un panneau qui coupe = non), menus par leurs `PopupRoot` (pixels non transparents), survol lu dans les déclencheurs et gestionnaires (jamais la souris), zoom des tuiles par `MouseEnter` simulé (témoin : une affiche), transitions lues dans les valeurs de WPF à chaque image (opacité, place, taille, transformation des éléments animés, pas l’arbre entier ; les pixels seulement avant/après : RenderTargetBitmap à chaque image prenait 100 à 150 ms sur le Dell, PrintWindow est figé pour une fenêtre sous une autre), détail image par image dans les notes d’une transition lue « sans animation ». Fondu d’une page qui part (`Motion.HideDrawnAsync`) : la page dessous découverte et la page à 0,999 d’abord, horloge du fondu partie après une image retenue (horloge murale, `DrawnAsync`) : sinon ces premières images lourdes (100 ms sur le Dell) avalaient le fondu. Fenêtre à l’écran à (0, 0) (WPF garde un menu sur l’écran, pas dans la fenêtre), jamais activée, `HWND_BOTTOM`. `DOTNET_DISABLE_GUI_ERRORS=1` (sans runtime, l’apphost ouvrait une boîte qui attendait). Nuit sur le Dell d’ogsas : `tools/ui-audit-nightly.ps1` (`-Install` = tâche « Mira - audit de l’interface » à 3 h 30 par `conhost --headless`, clone `C:\Apps\mira-qa\repo`, SDK `C:\Apps\mira-qa\dotnet`, rapports `C:\Apps\mira-qa\reports\<date>` 14 nuits + `latest.json`, sauté si clavier/souris < 20 min, Direct3D plein écran, présentation ou un lecteur devant ; pas « occupé » : le kiosque de Vigie l’est toute la journée). Rapports jamais publiés (affiches et titres de la bibliothèque d’ogsas). Pas de Mac. - Budgets de performance (2026-11-07, piste 11 de l'audit) : `tools/perf/budget.mjs` + `budgets.json` (chiffres d'origine dans sa note `about`) tiennent `--smooth-check` Windows (job `smooth`, deux placements), Mac (étape « Smoothness budgets » de `mac.yml`, clics seulement : le taux d'écran de la VM varie de 10 à 39 Hz) `idle-check.ps1` (job `build`) et l'ouverture de l'iPhone (lignes `MIRA-OPENING` de `testOpening`, `tools/perf/ios-opening.mjs`, étape « Opening budgets » d'`ios.yml`) ; `fail` à 2-4 × le pire relevé, sinon `warn` ; au-delà d'un `fail`, mesure refaite, échec seulement si les deux runs le sont ; sur PR, comparé à l'artefact du dernier `main` réussi (`Mira-smooth`, `Mira-perf` par `tools/perf/main-reports.sh`, `actions: read`), avertissement seulement. Phase renommée dans un contrôle = renommée dans `budgets.json` (phase absente = échec, test). Changer un budget seulement avec les chiffres qui le justifient.
- Defender et compilation reproductible : `defender.yml` par `workflow_dispatch` (`commit`, `release=vX.Y.Z`) compile sur un runner propre, le fait scanner par le Defender du runner (cloud activé par `Set-MpPreference`, sinon aucun verdict « !ml ») et compare avec le zip publié ; `node tools/compare-assemblies.mjs <a.dll> <b.dll>` compare deux compilations d'un même commit partie par partie (corps des méthodes, tas de métadonnées, ressources) : un diff d'octets ne vaut rien, une chaîne plus longue décale tout. Deux compilations honnêtes diffèrent par le MVID, les versions des outils du SDK dans `#Blob`, le hachage du générateur de regex, `\` ou `/` dans les noms de ressources selon l'OS ; version informationnelle = `x.y.z` seule depuis le 2026-10-16 (`IncludeSourceRevisionInInformationalVersion` false : c'est le `ProductVersion` que SignPath vérifie), plus de `+<sha>` qui changeait l'empreinte à chaque commit.
- Publication (PC de l'utilisateur, où est la clé ; plus rien n'y est compilé) : `git checkout main; git pull --ff-only; .\tools\release.ps1`. Exige releases immuables, gh, clé (`Mira.Release check-key`), arbre propre, `main` = GitHub, tag absent, entrée `WhatsNew.json` (notes ; `--unsigned` avec `-Unsigned`) ; attend `ci.yml` vert sur ce commit (échec = relancé une fois) ; brouillon `--draft --target <commit>` sans fichier, branche `release/vX.Y.Z` au commit (`main` peut bouger ; refusée = `main`), y lance `windows.yml`/`web.yml`/`mac.yml`/`ios.yml` (`-f release=vX.Y.Z -f commit=<sha>`, `-f sign=false` avec `-Unsigned`), juge chaque exécution sur son job `release` (fichiers joints), relance seul ce qui a échoué (2 fois par lancement : Mac sans machine, tests instables), tests déjà passés en PR en `continue-on-error` pendant une release (simulateur iPhone, Tailscale Mac, icônes : avertissements) ; reprise : `.artifacts/release-X.Y.Z.json` (commit, branche, exécutions), relancer la même commande ne refait que ce qui manque ; appels à GitHub essayés 4 fois ; `tools/attach-to-draft.sh` (job `release` des 4 workflows) : rejouable, garde un fichier de même SHA-256, remplace le reste ; avant lui, `actions/attest-build-provenance` sur chaque fichier (`gh attestation verify <fichier> -R sasou-web/Mira`) ; après lui, Windows et Mac, `tools/virustotal.sh` (secret `VIRUSTOTAL_API_KEY` ; absent = rien d’envoyé ; jamais un échec : sortie 0 et `continue-on-error`, une requête toutes les 16 s (API gratuite : 4 par minute), 429 = une minute ; tests `tools/virustotal.test.mjs` avec un faux `curl`) ; page du wiki `verify` (« Vérifier ton téléchargement »), liée par les notes de release et le README ; artefacts `overwrite: true` ; contrôle `tools/release-check.ps1` (faux `gh`/`git`/`dotnet` en fonctions, `ci.yml`, Windows PowerShell 5.1) ; prend leurs artefacts (`Mira-win-x64-release` → `dist/packages`, `Mira-mac-arm64`, `Mira-web-release` → `dist/release`, `Mira-ios` → `dist/ios`), vérifie les signatures Authenticode (`check-signed.ps1`, sauf `-Unsigned`), signe (`manifest --others`), compare le `digest` des 14 fichiers (12 envoyés par `github-actions[bot]` ; 12 jusqu'à la 0.8.5 ; manquant ou différent = job `release` relancé), publie, vérifie `immutable`, retire la branche, lance `bump.yml` du tap Homebrew. `-DryRun` laisse le brouillon. `windows.yml` : `package.ps1 -Publish` → artefact des 4 fichiers de Mira → action SignPath (`project-slug mira`, `release-signing`, config `app`, paramètre `version`, approbation d'ogsas, 1 h au plus) → `-From` (zip, portable, installateur) → artefact `Mira-setup.exe` → SignPath (config `installer`) → `-Hash` ; secrets `SIGNPATH_API_TOKEN`, `SIGNPATH_ORGANIZATION_ID` ; `sign=false` = sans SignPath.
