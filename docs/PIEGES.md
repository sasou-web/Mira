# Pitfalls (fragile, do not touch without a reason)

> What the code, Jellyfin, Windows, macOS and iOS do wrong or unexpectedly, found the hard way. Read the section for the area you are touching before changing it; add any new pitfall here.

## Extension and Quick Connect
- Reading a request’s token (2026-11-19): never with a regular expression, always `SessionTokens.Of` (`GuestController.Tokens`). Jellyfin (its `AuthorizationContext`, the same in 10.9, 10.10 and 12.x) cuts the header at the first space, trims the name (`Token =`), decodes the value with `WebUtility.UrlDecode` (`%61b…` = `ab…`), keeps the name after an empty value (`Token=,"ab…"`), reads only the first value of the header, and joins several `X-Emby-Token` or `ApiKey` with a comma. A simpler reading let a guest get past `TunnelGuard` at home (#662, reported before 0.9.15). `/Mira/home` is not affected: it reads the session through Jellyfin’s `[Authorize]` and its own `X-Mira-Home` header.
- SyncPlay: Jellyfin’s API never gives a group’s queue (`SyncPlay/List`, `SyncPlay/{id}`: name, state, members). `PartyTitles` reads it in `SyncPlayManager`: field found by its type (text → `IGroupStateContext` dictionary, `_sessionToGroupMap` from 10.9 to 12.4), then `PlayQueue.GetPlaylist()` of the public interface, under `lock (group)` like Jellyfin. Field not found = the guest reaches no title (log: “SyncPlay's groups could not be read”); `check.mjs` sees it on each Jellyfin of `web.yml`.
- Any request from the extension to Jellyfin that carries a guest’s token must carry `JellyfinLoopback.Header` (`CallAsync` sets it, `GuestController.ForwardAsync` and `HlsController` too), otherwise `TunnelGuard` refuses it (404) outside `/Mira/guest/`.
- Quick Connect (sign in with a code): when disabled, Jellyfin answers 401 to `QuickConnect/Authorize` and `Initiate`; check `QuickConnect/Enabled` before allowing (otherwise 401 = end of session on Windows and Mac). Code forgotten by Jellyfin = 404 on `Connect`.
- Extension: inherits from `BasePlugin<BasePluginConfiguration>` (otherwise null version, “malfunctioned”); `WebFiles.Types` knows each extension served (unknown type → `Unserved`, failing test). With `MIRA_WEB_DIR`, the page is not kept: “server off” is tested with the built extension.
- A Jellyfin API call that changes signature (the return type counts): `MissingMethodException` only when the calling method runs, sometimes hours after startup (`ILibraryManager.GetItemList`: `List<BaseItem>` up to 12.1, another type in 12.4; seen on the Dell on 2026-11-19 in `TvdbOrders`; `GetItemsResult(...).Items` works everywhere). Guarded by the “Bindings” step of `web.yml` (`tools/extension/bindings`: each method compiled by the JIT against the image’s `/jellyfin`); locally: `dotnet build tools/extension/bindings -c Release -o .artifacts/bindings` then `dotnet .artifacts/bindings/mira-bindings.dll </jellyfin folder copied from the image> <Mira.Jellyfin.dll>`.
- `web.yml` (until 2026-11-19) did not read Jellyfin’s log and never waited for the extension’s loops (`SubtitleAutomation` every minute, `TvdbOrders` every 10 min): an exception there shows in no API response (subtitles on read-only media, `MissingMethodException` from 12.4). Now `tools/extension/log.mjs` fails the job and the loops run every 10 s (`MIRA_CHECK_TICK_SECONDS`, `CheckTick.cs`, never anywhere but CI). A fixed “unknown” id is not one: `00000000000000000000000000000001` is a filler row of Jellyfin 10.11; `check.mjs` draws one at random.
- Accounts and devices (12.1, checked on 2026-11-19): no more “Easy PIN” (`Users/{id}/EasyPassword` = 404, `HasConfiguredEasyPassword` stays in the DTO); a sign-in of another account under the same `DeviceId` does NOT close the first one’s session (both tokens work), only a new sign-in of the same account on the same device replaces its token; `DELETE Devices?id=` closes every session of that id, all accounts together, and answers 400 (12.1) or 404 (10.9) for an unknown id (`Devices/Info?id=` first); `ISessionManager.AuthenticateDirect` opens a session without a password and without checking `IsDisabled` (check it yourself; the home does).
- Account passwords (12.1, checked on 2026-11-20): `HasPassword` of `GET Users` is `true` for an account created without a password (`Users/New` without `Password`: hash of an empty string, or a null `Password`); only the extension knows (`AccountPasswords`, `$PBKDF2-SHA512$iterations=…$sel$hachage`). `IUserManager`: `Users` property in 10.x, `GetUsers()` method in 12.x, entity moved: through reflection. An administrator who changes another account’s password (`POST Users/Password?userId=`, `Users/{id}/Password` in 10.9) closes all its sessions; changing your own keeps the current session and closes the others; wrong current password = 403. `DELETE Devices?id=` of an unknown device = 400 (not 404) in 12.1.
## Jellyfin and test media
- Network (12.1): `EnableRemoteAccess` and `LocalNetworkSubnets` changed through `POST System/Configuration/network` apply right away, but `KnownProxies` only after a restart (before that, `X-Forwarded-For` is ignored and the session comes from 127.0.0.1). `Sessions` gives `RemoteEndPoint` (address seen, after the known proxy). A non-administrator account reads these settings without being able to write them.
- Virtual episodes (12.1): missing from `Shows/{id}/Episodes` and `Shows/{id}/Seasons` (except with the account’s `DisplayMissingEpisodes`, Jellyfin’s “Display missing episodes”: then a whole season of missing ones too; hence `isMissing=false` on each of these requests, iPhone included, which keeps the “Virtual” season Jellyfin makes for episodes without a season folder; a virtual one played = `NoCompatibleStream`), from `Items?parentId=<series>&recursive=true`, NextUp, Latest and `ChildCount`; present in `Items?recursive=true&locationTypes=Virtual` (the whole library, filter by `SeriesId`), `parentId=<season>` and `Shows/Upcoming`. `isMissing=true` with `parentId` returns the real ones too. `setup.mjs` leaves them out of the title count (no runtime, never “played”). `Folder.GetRecursiveChildren()` throws `MissingMethodException` on 12.1 (fake extension: `GetItemsResult`).
- Title in several files (12.1; `cd1`/`cd2`, `part1`, `disc2`… in the same folder, movies and episodes): a single title with `PartCount`, whose runtime, streams and progress are those of the 1st part (“watched” at the end of it); the others through `Videos/{id}/AdditionalParts?userId=` (type `Video`, hidden from the library, their own `UserData`, missing from `UserItems/Resume`): `MovieParts` (Core, iPhone `Player/MovieParts.swift`, case `parts.json`) chains them and chooses where to resume, never in a group; kept whole on this PC, this Mac and this iPhone (`OfflineCopies`, `KeptCopy`: each other part in `part-2`, `part-3`… of the title’s folder, described in `mira-copy.json`, downloaded before the title’s file).
- Collections (12.1): a collection created under a name already taken, case aside, or whose folder is (`"<>|:*?\/` changed into spaces) replaces the old one, which loses its titles: `NameProblem` refuses before sending (list read again). Once renamed, a collection keeps its first folder (its old name stays taken). `DELETE Items/{id}` erases a movie’s files: check `Type == BoxSet` first.
- Subtitle provider: ids without `_` (Jellyfin prefixes `<md5 of the name>_` and cuts at the first one); `IMediaSourceManager.GetMediaStreams(Guid)` changed its return type in 12.x: called through reflection (otherwise `MissingMethodException`); Jellyfin’s automatic downloader takes the first result and downloads again at each pass (`.fre.0.srt`, `.fre.1.srt`): `AlreadyHas` (file beside it, 2 hr cache). ; during the scan, Jellyfin asks for an episode’s subtitles before numbering it: season and number taken from the request or the file name (`Numbers`, and in `SubtitleMatch.Score`), otherwise nothing automatic (without them, a source answers for the whole series); source languages (seen on the real ones on 2026-11-12): OpenSubtitles answers nothing to `pt` or `zh`, only to `pt-br`, `pt-pt`, `zh-cn`, `zh-tw` (`OpenSubtitlesApi.Languages`); SubDL files Brazilian under `BR_PT` and Traditional Chinese under `ZH_BG` (`SubDlApi.Languages`, read by `SubtitleLanguages.Three`); `ISubtitleManager.DownloadSubtitles`/`UploadSubtitle` write the file without reading the title again (Jellyfin’s API does `QueueRefresh` afterwards): `SubtitleAutomation.Reread`, otherwise nothing is listed before the next scan; other versions of a movie (“Film - 720p.mkv”) = owned items (`OwnerId`), never `ItemAdded` nor in `Items`: reached through `OtherVersions` (`LocalAlternateVersions` + `GetNewItemId`, `GetLocalAlternateVersionIds` missing from 12.x).
- 12.1’s `PlaybackInfo` with `StartTimeTicks`, account without the right to convert under a bitrate cap: the external subtitle of the file as is arrives cut at the start (`/Subtitles/0/300000000/Stream.subrip`, shifted); `ServerStreams.Beside` puts `0` back. The subtitles’ address answers without a token.
- `PlaybackInfo` (12.1) reads `AudioStreamIndex`/`SubtitleStreamIndex` only if `MediaSourceId` names the file; otherwise its default tracks (subtitles according to the account’s `SubtitleMode`, image-based ones burned in: `SubtitleMethod=Encode`), and a `MediaSourceId` of no file = no source. Core reads what `TranscodingUrl` says (`AudioStreamIndex`, `ServerStreams.Drawn`) and asks again naming the file; the iPhone reads the whole title (`PlayerSession.loadFiles`) when it comes from a list without `MediaSources` (Home).
- mpv: `http-header-fields` is a comma-separated list: those in the `Authorization` header are escaped as `\,` (otherwise Jellyfin answers 400). `--start` on a conversion’s `master.m3u8` works (complete playlist, checked on 12.1).
- While starting, Jellyfin 12 answers `System/Info/Public` (camelCase) and 503 to the rest: only `System/Ping` proves it is ready; it is not a “foreign server”.
- Jellyfin 12.1: the WebSocket is taken by its middleware at any path, before routing (an extension controller never gets one); `X-Emby-Token` is no longer read (`Authorization: MediaBrowser Token="…"` or `ApiKey=`); Kestrel decodes `%2e%2e` then normalizes: `/Mira/%2e%2e/Users/Public` reaches `/Users/Public`; Funnel cleans the path (`path.Clean`) before comparing it with `/Mira` (Tailscale 1.104.4 code copied in front of a real 12.1, 30 variants refused), and `TunnelGuard` (`IStartupFilter`, honored by 12.1, before any Jellyfin middleware, WebSocket included) lets a request with `Tailscale-Funnel-Request` (set by Tailscale 1.72+) through only to Mira’s pages (`/Mira`) and `/Mira/guest/…`. To try a diverted address in .NET: `UriCreationOptions.DangerousDisablePathAndQueryCanonicalization` (otherwise `HttpClient` resolves `%2e%2e`). Jellyfin writes the request’s `ApiKey` into its playlists’ addresses: the gateway puts it back into the request.
- `System/Restart` restarts Jellyfin in the same process: an extension reinstalled under a version number already loaded keeps the old code (same assembly identity); in tests, `docker restart`.
- `EnableSubtitlesInManifest` is read only for `live.m3u8`: for a movie, `SubtitleMethod=Hls` (without `SubtitleStreamIndex`, everything as `DEFAULT=NO`); `SubtitleMethod=Encode` for -1 is not burning in. ASS/SSA never converted by the profile (`SupportsSubtitleConversionTo`).
- HLS TS segments at 10 s, fMP4 at 0, HLS WebVTT at `MPEGTS:900000` hard-coded: Apple’s player cares about them.
- 12.1’s SyncPlay: a closed WebSocket ends the session, and an empty group disappears in less than a second (iPhone in Messages); a device that joins (same group) is a newcomer: `PlayQueue` of the same `PlaylistItemId` and group waiting for it, to answer with `Ready` (player open) or `SetIgnoreWait` (closed), otherwise everyone stays paused. One SyncPlay request at a time, in order (Windows `SendGroup`, Mac `WatchGroup.Send`): a Buffering received after the Ready sent right behind it blocks the group on that device (forever on 10.x, 30 s on 12.x, which gives up waiting).
- Jellyfin 12.1: `allowVideoStreamCopy=false` written only for HLS, `VideoCodec=` even when it copies (`copiesVideo` reads `TranscodeReasons`); no longer reads `BreakOnNonKeyFrames`, `MinSegments`, nor the codec tags; does not convert again a VP9 of unknown level (the Chromium cascade starts from an H.264).
- “Move to Recycle Bin” (Windows, Jellyfin’s PC, administrator; `TitleFiles`, `RecycleBin`, `MainWindow.TitleFiles.cs`): `IFileOperation` (`FOF_ALLOWUNDO` + `FOFX_RECYCLEONDELETE`, no more `FOF_WANTNUKEWARNING`: its Windows question offered permanent deletion), and an `IFileOperationProgressSink` whose `PreDeleteItem` returns `E_ABORT` when `TSF_DELETE_RECYCLE_IF_POSSIBLE` is missing (otherwise Windows erases for good, silently, what the Recycle Bin cannot keep); `GetDriveType` of the volume (`GetVolumePathName`: the Dell’s WD is mounted in a folder of C:) and not of the letter; never Jellyfin’s `DELETE Items/{id}` (erases for good); strictly inside a library folder; the movie’s folder only when there is no other video outside the extras folders; never a series’ folder for an episode or a season; then `Library/Media/Updated` “Deleted”. `MediaItem.Path` comes from the request for a single title (the episode list has none: `ItemAsync`, or `EpisodeFilesAsync` for a season’s `MediaSources`).
- Empty library folder: Jellyfin no longer validates it (“Library folder … is inaccessible or empty, skipping”, even through `Library/Refresh`), the last deleted title stays; hence `LibraryMarker` (hidden `.mira`, counted by Jellyfin: `AttributesToSkip = 0`), placed by `MediaFolders.Create` and when Mira for Windows signs in on Jellyfin’s PC (administrator, `MarkLibraryFoldersAsync`), scan if the folder was empty. A change made while Jellyfin is stopped is only seen at the next scan (12 hr).
- `SaveSubtitlesWithMedia`: true = uploaded subtitles written next to the media ONLY (500 if Jellyfin can only read the folder, the case of an install by Mira before 0.9.13); false = in its metadata only. Mira switches the title’s library to false on that 500 (administrator), `JellyfinSetup` creates the libraries that way.
- Extras (10.9 to 12.4): `BaseItem.RefreshExtras` reads all of a title’s extras again in parallel with no limit (`Task.WhenAll`) as soon as their list changes or in `FullRefresh`; `LibraryScanFanoutConcurrency`/`LibraryMetadataRefreshConcurrency` do not cover them. `Folder.ValidateChildren` of a series starts with `series.RefreshMetadata` (extras included): to read seasons and episodes again without them, `IMetadataContainer.RefreshAllMetadata`. `DateLastRefreshed` is not in the DTOs. To count ffprobe runs in a container: replace `/usr/lib/jellyfin-ffmpeg/ffprobe` with a script that logs start/end and sleeps 2 s (`DECISIONS` → “Bonus jamais analysés tous à la fois”).
- `SaveLocalMetadata` (12.1): a library scan writes nothing for a title already known; “Refresh” in `Default` neither; `FullRefresh` without replacing anything writes the NFO (even without Internet) and keeps what was corrected. An image already kept stays in `metadata/library/`: only an image given again (`POST Items/{id}/Images/{type}`, in base64) goes next to the files (`folder.jpg`, `backdropN.png`, `<episode>-thumb.jpg`), the old one erased, NFO rewritten with its path. `POST …/Images/Backdrop/{index}` ignores the index: appended at the end. A movie alone in its folder: `movie.nfo` (not `<name>.nfo`). Without write access, Jellyfin stores the image in its data (its fallback path) and does not write the NFO, with no error returned. A Jellyfin without the TheTVDB plugin does not show `tvdbid` (kept in the NFO). Jellyfin deletes the old image without catching a refusal (`ImageSaver`): it needs the right to delete what it wrote (CREATOR OWNER).
- `web.yml` matrix: `setup.mjs` waits for the 18 titles (4 movies, 14 episodes) and the 6 series before handing back (Jellyfin 12.4 had not yet scanned Anime at 14: “Animes : rien”); if the media of `media.sh` change, change these numbers; on 10.9 and 10.10, “More from” keeps the collection’s movie (no collection row); the start of “together” waits up to 60 s (slow conversion on a busy runner); “Test media” (ffmpeg) got stuck for 30 min on a runner: run it again.
- Tests: ffmpeg’s `-shortest` counts the subtitles (duration through `-t`); `.srt` without accents (Jellyfin guesses the encoding of a one-line file badly); `MinResumeDurationSeconds` at 1 (`setup.mjs`; 5 min by default); Mac without `md5sum` or `base64 -w`; the Mac VM refuses copied 10-bit HDR10 HEVC.
- A season deleted from disk: Jellyfin still lists it for several minutes (Dell, 12.4, 2026-11-19: folder gone at 15:39:40, `LibraryMonitor` at 15:40:41, `Removing item` at 15:43:46 after the series was refreshed by AniDB, AniList, TheTVDB…), even after `Library/Media/Updated`. With “Missing Episode Fetcher”, it immediately recreates it as a virtual season (normal: “missing” on the title page).
- Changing a series’ display order (`DisplayOrder`) is not enough with the TheTVDB plugin: seasons and episodes are read again through the TheTVDB id already kept (the one of the old order). Remove that id (`ProviderIds`) before reading again; the virtual ones from the “Missing Episode Fetcher” are reconciled only at `RefreshCompleted` (Jellyfin’s queue or a recursive `ValidateChildren`), not after `RefreshSingleItem` nor `RefreshAllMetadata`.
## Windows: firewall, service, elevation
- Firewall: a block wins over any allow rule; the “Allow access” prompt blocks the unticked profiles. `HNetCfg.FwPolicy2` as `dynamic` (IDispatch by name: a badly ordered `ComImport` interface would call another method, as administrator); indexed properties `policy.FirewallEnabled[profile]`. Mira’s rule judged on its content (`JellyfinFirewall.MiraRule`), profiles `JellyfinStartup.RuleProfiles`; judgment of both origins in Core (`JellyfinFirewall.Phones`, testable under Linux).
- Network adapters’ profile: `MSFT_NetConnectionProfile` (WMI, `WbemScripting.SWbemLocator` as `dynamic`, no rights needed); `InterfaceAlias` = `NetworkInterface.Name`. “Make it private”: `ApplyAsync(port, privateNetwork: true)`, `Put_(1)` in the script, never a domain, refusal read back = `KeptPublic`.
- “Set everything up”: a `ToDo` step must be doable by Mira (otherwise the permission prompt comes back at each click); what Mira does not change (block everything, rule without a program, program not found) is `Yours`; Jellyfin silent (`System/Ping`): nothing is concluded.
- Elevated script: Windows PowerShell 5.1, `-EncodedCommand`, neither `??` nor ternary, no cmdlet or module (`$PSModuleAutoLoadingPreference = 'None'`), texts in base64, line ≤ 30,000 characters (`MaximumArguments`). Windows tests through the same script without elevation; under Linux, `pwsh` with fake `sc.exe`/`netsh.exe` in the current folder (`[Environment]::SystemDirectory` empty).
- `sc failure … restart/…/restart/60000//0`: Windows repeats the last action, the fourth one, empty, stops the restarts (CI test on `FailureActions`).
- Network Service: read access on `Films`, `Séries`, `Animes` only (traversing is enough); 0.7.4 and earlier had it on the root, removal in `docs/INSTALLATION.md`.
## Windows: app
- Global handler (`App.xaml.cs`): window open → `Handled = true` and a message; before `Show()` or while closing (`IsClosing`) → `Shutdown(1)`, otherwise a process without a window keeps the mutex. `Window_Closing` (and the Mac’s `OnClosing`): each step inside `Attempt` (`errors.log`), closing in `finally`. `--windows-check` writes `failure.txt` even without a window. A duplicate key in `Cinema.xaml` (app resources) crashes Mira before any handler (code -532462766, no log): “Palette” test. Mac: `Dispatcher.UIThread.UnhandledException`, same rule, `--self-check` left to crash.
- Language: a `static readonly` or a `const` initialized with `L(…)` freezes the language of its first use (computed property); a compared text (`CopyState(...) == Paused`) compares with the same property; a class’s `Count` hides `Lang`’s (write `Lang.Count`).
- Windows shutdown or Restart Manager: `SessionEnding` then closing without waiting; what must survive goes into `KeepForNextStart` (synchronous, before the first `await` of `Window_Closing`) and `SessionEnding` (“stop” queued, 1.5 s at most).
- `InstanceActivation`: channel off the UI thread, created right after the mutex (otherwise a false “already open”); answers `shown`/`starting`/`closing` (the relaunch waits for the mutex then redoes the checks).
- Shrinking and enlarging the player (`MainWindow.PlayerMorph.cs`, 2026-11-04, measured on ogsas’s PC, 4K at 240 Hz): the real video window moves, at each frame of the screen (`VideoHost.BeginMove`/`Move`/`EndMove`, a thread on `DwmFlush` that posts each step to the UI thread: `CompositionTarget.Rendering` comes only at 60-100 Hz and irregularly when WPF has nothing to draw; a clock and not counted frames, started after 3 WPF frames so that the page’s first drawing, heavy in 4K, does not hold back the start; controls reopened by the next tick, not on arrival), mpv plays meanwhile, at a single size: Windows stretches what it draws (flip model, `DXGI_SCALING_STRETCH`). `VideoHost` subclasses mpv’s window for the duration of the move: the `WM_SIZE` messages stop there, mpv takes its size from that message and not from `GetClientRect`, so `DrawAt` tells it the final size right away when growing (sharp picture) and `EndMove` on landing when shrinking; one size per frame made it reallocate everything (choppy film, graphics card busy under the move). `HwndHost` puts its window back where the layout wants at each `WM_WINDOWPOSCHANGING`: `VideoHost.WndProc` skips it during a move (without that, `SetWindowPos` does nothing). Do not go back to `screenshot-raw` during playback: it blocks mpv’s main thread (sound skips), and a frozen picture laid on top gives a black frame at each end (WPF has not presented yet when the HWND hides). `IDCompositionDevice::CreateSurfaceFromHwnd` tried: E_INVALIDARG, and a `WS_EX_LAYERED` child no longer shows mpv’s swapchain. Controls overlay closed meanwhile (`_morphing`), mpv released after the move (`_releaseWhen`). Opening and closing: `Playback/WindowShade.cs`, a black sheet from Windows’ compositor (`Windows.UI.Composition`, `DesktopWindowTarget` at the top of the stack) over the whole window, video and controls included; the only way to fade above mpv’s HWND, attached only when it shows. The HWND stays whole but hidden by an empty region (`Conceal`) until mpv has its first frame (`playback-restart`, `RevealVideo`): a WPF `Hidden` would leave it at 1 × 1; the sheet lifts before that only for a slow start (1.2 s, spinner). Closing: black, page underneath, sheet lifted; mini player: slides off the edge. Measuring: `MIRA_FRAME_PROBE=<file>` (`FrameProbe`, one line per transition), `INFO transition` lines of the player check.
- mpv window hidden by WPF (`HwndHost`): `ShowWindowAsync(SW_HIDE)` is posted, while a `SetWindowPos` on the same thread (`OnWindowPositionChanged`, `EndMove`) is immediate: put back in place before the hiding arrives, it shows there with its last frame (0.9.9: “flashbang” when closing the mini player). Whatever takes it out of view hides it right away (`VideoHost.PutAway`), `EndMove` puts nothing back from a hidden window; checked by `PutBackShown` and `VideoWatch` (`--player-check`).
- Player layer: transparent child only with `supportedOS` Windows 8+ in `app.manifest` (otherwise Windows refuses `WS_EX_LAYERED` on a child); `UsesPerPixelTransparency`, never with `UsesPerPixelOpacity`; `TakeActivatingClick`: initial mark `long.MinValue / 2` (`TickCount64 - long.MinValue` overflows: every click would be an “activation” click). The menus’ `Popup` stays a separate window (missing from a window share).
- Windows player menus (`PlayerOptionsPopup`, `StaysOpen=False`): WPF closes the menu in `OnPreviewMouseLeftButtonDown` then, the capture released, gives the press to whatever is under the pointer (the picture: pause or play; the menu’s button: reopened): `PlayerOptions_PreviewMouseDown` stops it (`Handled`), another menu’s button opens it on release (`MenuButton_MouseUp`, `handledEventsToo`). `ClickCount` counts the stopped press (Avalonia: always, same window; WPF: when its position in the menu’s window falls on that of the next click): `_pressClosedMenu` (Mac: `_pictureClickAt`), otherwise the next click would be a double click (full screen). Checked with real clicks (`RealMenuPresses`, only on a runner: window put on screen for the duration of the check).
- Text: `WindowChrome`’s `GlassFrameThickness` (DWM shadow and corners) turns all of WPF’s text gray, even with `ClearTypeHint` on the window (clip of a `ScrollViewer`, `Squircle`): `ClearText` sets `ClearTypeHint.Enabled` by default on each `TextBlock` and on WPF’s internal `TextBoxView` (typed text), `Auto` under `PlayerOverlay` (transparent window). Measuring: `PrintWindow` (`PW_RENDERFULLCONTENT`) and colored pixels; `RenderTargetBitmap` always draws in gray.
- Window: `ScreenFit.Place` in physical pixels at `SourceInitialized` (move, then size); `Maximized` afterwards, never in the constructor. Snap Layouts: `SnapHook` (`HTMAXBUTTON`) added after `WindowChrome`’s hook; WPF no longer sees the mouse on that button.
- UX pass of 2026-11-14 (library and title pages, notes `/mnt/project-files/passe-ux-2026-11-14/bibliotheque.md`): WPF keeps a drop-down menu on the screen, not in the window: `DropDownRoom.FitsWindow` (`ComboBox` style of `Cinema.xaml`) places it below or above its box depending on the room; the library under a page that covers it is hidden from UI Automation (`CoverableGrid.Covered`, set with `UpdateLibraryCover`); a row that scrolls sideways fades out at the edge where it continues (`EdgeFade`, Windows and Mac); the filters’ Genre and Year = those of the page (`FiltersAsync(types)`, one genre per name: `GenreItem`).
- Narrator: the `Button` style binds `AutomationProperties.Name` to the content’s text (`Accessible.ContentName`); a lone icon has its name; `CaptureAsync` fails on a visible control without a name (`AssertNamed`). `System.Windows.Readability` exists: Core’s class is `Legibility`.
- `HttpClient` timeout (12 s) = `TaskCanceledException`, caller’s token intact: ignore a cancellation only `when (ct.IsCancellationRequested)` with the token taken at the start (`_connectionLifetime` changes with the account), otherwise a silent server gives no notice; a `quiet` refresh ignores it too as long as the page shows something. `IsExpected`/`Errors.Expected` → `ExpectedErrors.Are`: only `UserInputException` is an expected `ArgumentException`, any other goes to the global handler.
- Unreadable settings: copy `settings.json.bad-<date>` (Windows and Mac); `TrySaveSettings` never throws; hiding `SettingsOverlay` calls `AutoSaveSettings()` first; startup notice through `AddNotice`. `FileShare.None` is only advisory outside Windows.
- `LibraryStore`: `CreateSchema`, `quick_check(1)` and `Prune` in the same `try`; database set aside on 11, 26, 266 (`IOERR_READ`) and 8458 (`IOERR_CORRUPTFS`); disk full, lock or read-only bubble up. `quick_check` describes in text without throwing (except page 1). EIO can be simulated under Linux: LD_PRELOAD on `pread64`. No `:memory:`. Cache = a bonus (`TryCache`); `Save` skips an identical page: every write to `cache` goes through `Save`.
- Images: decoded at the displayed size × scale (`Artwork.Pixels`, width in the key); the grid loads on approach (`LoadVisibleArtwork`): a screenshot waits for `ImageReady`. Carousel at 30 Hz stopped when paused (`UpdateHeroClock` at each new cause). `SyncService` sleeps with nothing to send (`Wake()`); “Offline” comes from `_offlineSince`.
- `BitmapCache` (posters, `Motion.Page`): WPF makes it at the system’s scale (main screen at Windows startup), not that of the window’s screen: `RenderCache.UseScale` (`RenderAtScale`, text zoom included); a ×2 screenshot draws without it. A poster image made or released redraws the page: never while a page is arriving (`QuietUntil`).
- Sleep: `_fileOpen` from `Load` to END_FILE; reopening the stream skips the old one’s end (`_skipEnds`); an end during sleep or before Jellyfin’s answer is never the end of a title; a reopened stream that fails is never “watched”.
