# Mira

## Objectif
Client Jellyfin « cinéma » : une app Windows native avec mpv intégré, sa version Mac, et Mira web pour iPhone, iPad et
Android, servie par le serveur Jellyfin lui-même. Pour un particulier qui regarde sa bibliothèque chez lui et ailleurs.

## Stack
- .NET 10 (`global.json` : SDK 10.0.100, roll forward dans 10.0), C#. L'extension Jellyfin reste en `net8.0` (Jellyfin 10.9 et 10.10 tournent en .NET 8).
- Windows : WPF (`src/Mira.Desktop`), lecteur libmpv. Mac : Avalonia (`src/Mira.Mac`), libmpv embarquée, `.dmg`, macOS 15 ou plus (après la 0.7.4).
- Code commun : `src/Mira.Core`. Mira web : HTML, CSS, modules JS sans build (`src/Mira.Web`), vendorisés : hls.js, qrcode-generator.
- Extension : `src/Mira.Jellyfin`, compilée contre Jellyfin.Controller 10.9.11, chargée par Jellyfin 12.1. Serveur : Jellyfin 10.9 ou plus. `net8.0` n'est qu'une cible de compilation : l'extension tourne dans le .NET de Jellyfin (12.x = .NET 10, 10.11 = .NET 9, 10.9 et 10.10 = .NET 8), la fin de .NET 8 (2026-11-10) ne la concerne pas.

## Architecture (détail : `docs/ARCHITECTURE.md`, sécurité : `SECURITY.md`, tests : `docs/TESTS.md`)
- `src/Mira.Core/` : `JellyfinClient` (API, `InstallWebAppAsync`), `MiraWeb`/`MiraWebRelease` (dépôt, QR code, vérification), `PlayerText`, `WhatsNew.json`/`WhatsNew.cs`, `Updates/`, `JellyfinStartup` (plan et script élevé), `JellyfinFirewall` (jugement du pare-feu), `PhoneSetup` (étapes du téléphone), `JellyfinSubtitles` (sous-titres gardés sur Jellyfin), `ServerSearch` (serveur proposé à la connexion), `PlaybackFailures` (rapports « Lecture impossible » lus dans les journaux de Jellyfin), `ServerStream`/`StreamQuality` (qualité, conversion et coupures du lecteur Windows et Mac), `JellyfinBackups`/`JellyfinReleases` (sauvegarde et versions de Jellyfin), `TitleIdentity` (titres à corriger, « Identifier… »), `Subtitles/` (sous-titres automatiques : lecture des fichiers, note d'un candidat, vérification), `TorLink/`.
- `src/Mira.Desktop/` : `MainWindow.*.cs` par sujet (`Guide` = carte « Mira sur ton téléphone », `ServerDownloads` = Téléchargements loin du PC de Jellyfin, `JellyfinCare` = « Jellyfin sur ce PC »), harnais dans `Checks/` (lancés par `RunRequestedCheckAsync`, absents des paquets : `-p:MiraValidation=false`), `Services/JellyfinAutostart.cs` (lit le service et le pare-feu sans droits, lance le script élevé).
- `src/Mira.Jellyfin/` : `WebController` sert `/Mira`, `WebFiles` les fichiers intégrés (révision = empreinte), `HlsController` `/Mira/hls`, `ContentPolicy`, `TorLinkController`/`TorLinkRelay` `/Mira/torlink` (administrateurs ; séries suivies : `TorLinkRelay.Follows`, `plugins/configurations/Mira.follows.json`), `GuestController` `/Mira/guest` (passerelle des invités), `InvitesController` `/Mira/invites` (administrateurs), `GuestRoutes` (liste fermée), `GuestInvites` (liens, `plugins/configurations/Mira.invites.json`), `IdentifyController`/`IdentifyImages` `/Mira/identify/image` (administrateurs, affiches des propositions).
- `src/Mira.Web/` : `js/app.js` (routes `#/...`, bandeau « serveur injoignable », mise à jour par révision, « Nouveau dans Mira »), `api.js`, `views/*`, `identify.js`/`identify-sheet.js` (« Identifier… », `views/fix.js` « Titres à corriger »), `player/` (`player.js` lecteur d'Apple ou commandes de Mira, `stream.js` cascade et adresses, `timeline.js` passages et trickplay, `presentation.js` plein écran d'Apple, `profile.js`, `video.js` `<video>` partagée et `appleNative()`, `tracks.js` pistes, `failure.js` « Lecture impossible » et son rapport).
- `site/` : site vitrine miracinema.app (HTML, CSS, JS sans build, français à la racine, anglais dans `en/`), images tirées des captures du README par `tools/site/images.py`, icônes par `tools/site/icons.mjs` ; `site.yml` le publie sur GitHub Pages (push sur `main` et release publiée), `__VERSION__` = dernière release (`tools/site/build.mjs`).
- Tests : `tests/Mira.Core.Tests` (sans WPF, partout, Linux en CI), `tests/Mira.Tests` (les mêmes puis l'app Windows), `tools/web/unit` (Node). Exécutables d'assertions, pas `dotnet test` : `--filter <texte>`, `--list`, un échec n'arrête pas les suivants.
- `tools/` : `release.ps1`, `package.ps1` (`-Publish`/`-From`/`-Hash` pour `windows.yml`), `check-signed.ps1`, `publish.ps1` (`dist/Mira`), `mac/package.sh`, `web/`. Workflows : `ci.yml` (Linux + Windows), `windows.yml` (release : paquets Windows signés par SignPath), `mac.yml`, `web.yml` (Chromium et Safari). `installer/signpath/*.xml` : configurations d'artefact SignPath (copies ; celles de l'app SignPath font foi).
- Mira web : téléphone → `http://<serveur>:8096/Mira` → extension → app → API Jellyfin ; Safari lit le fichier tel quel, sinon HLS fMP4 (H.264 d'abord).

- CI d'une branche : `web.yml` et `ci.yml` par `workflow_dispatch` (`actions_run_trigger`) ; journaux : `get_job_logs` (le proxy refuse les zips).
- Vrai lecteur Windows en CI : `tools/player-check.ps1` (dans `ci.yml`) : libmpv de `MpvPackage.Current` (SourceForge, archive gardée par `actions/cache`), clip de 18 s à chapitres par l'ffmpeg d'`imageio-ffmpeg` (PyPI, `--require-hashes` ; pas d'ffmpeg sur les runners Windows), puis `Mira.exe --player-check` ; écran du runner 1024 × 768 : plein écran de contrôle ramené au moniteur (`CheckScreen`). Captures lisibles par `previews` (`player-window-capture`, `player-bar`, `mini-player`).
- Defender et compilation reproductible : `defender.yml` par `workflow_dispatch` (`commit`, `release=vX.Y.Z`) compile sur un runner propre, le fait scanner par le Defender du runner (cloud activé par `Set-MpPreference`, sinon aucun verdict « !ml ») et compare avec le zip publié ; `node tools/compare-assemblies.mjs <a.dll> <b.dll>` compare deux compilations d'un même commit partie par partie (corps des méthodes, tas de métadonnées, ressources) : un diff d'octets ne vaut rien, une chaîne plus longue décale tout. Deux compilations honnêtes diffèrent par le MVID, les versions des outils du SDK dans `#Blob`, le hachage du générateur de regex, `\` ou `/` dans les noms de ressources selon l'OS ; version informationnelle = `x.y.z` seule depuis le 2026-10-16 (`IncludeSourceRevisionInInformationalVersion` false : c'est le `ProductVersion` que SignPath vérifie), plus de `+<sha>` qui changeait l'empreinte à chaque commit.
- Audits : restauration en échec sur faille NuGet haute ou critique, même transitive (`NuGetAuditMode=all`) ; `dotnet list package --vulnerable --include-transitive` (`EnableWindowsTargeting=true` sous Linux) ; `dotnet format whitespace . --folder --verify-no-changes` (CI) ; eslint 9 et shellcheck depuis le scratchpad.
- Publication (PC de l'utilisateur, où est la clé ; plus rien n'y est compilé) : `git checkout main; git pull --ff-only; .\tools\release.ps1`. Exige releases immuables, gh, clé (`Mira.Release check-key`), arbre propre, `main` = GitHub, `ci.yml` vert sur ce commit, tag absent, entrée `WhatsNew.json` (notes ; `--unsigned` avec `-Unsigned`) ; brouillon `--draft --target <commit>` sans fichier, lance `windows.yml`/`web.yml`/`mac.yml` sur `main` (`-f release=vX.Y.Z -f commit=<sha>`, `-f sign=false` avec `-Unsigned`), prend leurs artefacts (`Mira-win-x64-release` → `dist/packages`, `Mira-mac-arm64`, `Mira-web-release` → `dist/release`), vérifie les signatures Authenticode (`check-signed.ps1`, sauf `-Unsigned`), signe (`manifest --others`), compare le `digest` des 12 fichiers (10 envoyés par `github-actions[bot]`), publie, vérifie `immutable`. `-DryRun` laisse le brouillon. `windows.yml` : `package.ps1 -Publish` → artefact des 4 fichiers de Mira → action SignPath (`project-slug mira`, `release-signing`, config `app`, paramètre `version`, approbation d'ogsas, 1 h au plus) → `-From` (zip, portable, installateur) → artefact `Mira-setup.exe` → SignPath (config `installer`) → `-Hash` ; secrets `SIGNPATH_API_TOKEN`, `SIGNPATH_ORGANIZATION_ID` ; `sign=false` = sans SignPath.

## Conventions
- Avertissement = erreur partout (`Directory.Build.props`) ; NU1900-NU1902 (faille basse ou moyenne, source d'avis injoignable) restent des avertissements. Dependabot (`.github/dependabot.yml`) : NuGet et actions, mensuel, groupé, 7 jours de recul, pas de majeure NuGet ni de `Jellyfin.Controller`.
- `.editorconfig` décrit le style réel (plusieurs instructions par ligne, initialiseurs compacts, `case` en bloc non indenté). Le formateur met quand même un bras de `switch` et un membre de `with { }` multiligne par ligne : pas d'option pour ça. Les formateurs des SDK 8 et 10 ne s'accordent pas sur le corps d'un `else foreach` sans accolades : des accolades.
- Docs en français, en tutoyant ; messages de commit en anglais. Interface en anglais et en français (anglais par défaut) : chaque texte écrit dans les deux langues là où il sert, `L("français", "English")` de `Lang` (Core, `using static Mira.Core.Lang`), pluriels par `Count`/`Plural`, heures et dates par `Time`/`Day`/`Date`, nombres par `Lang.Culture` ; langue = réglages (`PlayerSettings.Language`), sinon installation, sinon système ; appliquée au démarrage. Termes communs aux apps et à Mira web : `/mnt/project-files/anglais/glossaire.md`. Les tests partent en français (`TestRun`).
- Fins de ligne : CRLF pour `.cs`, `.xaml`, `.axaml` ; LF pour `.sh`, `.md`, `.yml`, `.json`, `.js`, `.mjs`, `.css`, `.html`, `.webmanifest` (`.gitattributes`).
- Chaque version a son entrée dans `WhatsNew.json` (résumé ≤ 100 caractères, 2 à 5 points, icônes dessinées par Mira, anglais dans `"en"` de l’entrée et de chaque point ; la page de release reste en français) : le test « Nouveautés : bienvenue… » le vérifie. `"web": true` sur un point que Mira web montre aussi (« Nouveau dans Mira », une fois sur le téléphone, texte valable pour lui) ; sans point marqué, le téléphone ne montre rien de cette version.
- `CHANGELOG.md` : section « Non publié » en haut, datée à la publication.
- Version : `<Version>` dans les csproj Desktop, Mac et Jellyfin ; ne la change qu'à la préparation d'une release demandée.
- Les PR se fusionnent en rebase (depuis la session, à la demande de l'utilisateur) ; la publication se fait depuis son PC.
- Windows : palette unique dans `Themes/Cinema.xaml` (fonds `Bg` à `LineStrong`, encres `Text` à `Dim`, `OnAccent`, états `Success`/`Warning`/`Danger`, calques `Hairline`, `Menu`, `Toast`, `Sheet`…), noms et neutres de Mira web ; XAML par `{StaticResource}` (`Muted`, `Faint`, `FocusRing` en `DynamicResource` : contraste élevé), code par `Palette.Get("Nom")`. Jamais une couleur écrite, sauf dégradés, contenu (démo, affiches, marque) et animations ; `Dim` jamais pour du texte (test de contraste).
- Mira web : design sombre (tokens dans `:root` de `app.css`), police Nunito Sans auto-hébergée, icônes Phosphor (`js/icons.js`). Taille de texte en `calc(Npx * var(--text))` (réglage « Taille du texte »), sauf libellés des onglets et du lecteur.
- Un test sans WPF va dans `tests/Mira.Core.Tests` (un fichier de Desktop sans WPF y est lié par son csproj) ; un test seulement Windows (chemins, liens physiques, DPAPI) dans `tests/Mira.Tests/Program.cs`. Code commun Windows/Mac dans Core (`IconPaths`, `MpvLists`, `MpvClient`, `PlaybackSession`, `SkipPlanner`) ; état du catalogue Windows dans `Catalog`, rangement TorLink dans `TorLinkPlacement`.

## Décisions (et pourquoi)
- 2026-10-08 — Mac en Avalonia avec libmpv embarquée — partage `Mira.Core` et le lecteur de Windows.
- 2026-10-09 — iPhone par une app web servie par une extension Jellyfin — ni App Store, ni compte Apple, ni AltStore, gratuit.
- 2026-10-11 — Dépôt de l'extension = `releases/download/vX.Y.Z/jellyfin-manifest.json` de la version de Mira pour Windows, vérifiée par sa signature ; releases en brouillon, signées en dernier, publiées d'un coup, immuables — Jellyfin ne vérifie qu'un MD5 fourni par la même release (SEC-02).
- 2026-10-09 — Une seule `<video>` partagée, débloquée au premier toucher (iOS n'autorise le son qu'après un geste) ; épisode suivant dans le même lecteur (`history.replaceState`) : retirer la `<video>` quitte le plein écran.
- 2026-10-09 — Profil d'appareil : H.264 avant HEVC en HLS — conversion le plus souvent sans réencodage.
- 2026-10-09 — iPhone et iPad : lecture seulement dans le plein écran d'Apple (pas de `playsinline`), demandé par l'utilisateur ; audio et sous-titres choisis sur la fiche (le menu d'Apple ne change pas l'audio d'une conversion).
- 2026-10-09 — `/Mira/` gardée un mois par le téléphone, révision vérifiée à chaque démarrage — s'ouvre PC éteint et attend le serveur ; pas de service worker en HTTP.
- 2026-10-10 — Dynamic Island : défaut d'iOS pour les apps de l'écran d'accueil, rien dans la page n'y change rien ; seul levier, la session audio `ambient` (seule mêlable, coupée par le mode silencieux) : option « Masquer la Dynamic Island », iPhone seulement, qui le dit.
- 2026-10-10 — Flux refusé alors que Jellyfin répond : vidéo convertie, puis tout converti (`lastResortProfile`, H.264 SDR ≤ 1080p, AAC stéréo), de là où il en était — baisser la qualité ne change rien (Jellyfin copie la vidéo sous le plafond) ; profil aligné sur jellyfin-web pour Safari (`VideoRangeType`, `IsInterlaced`, niveau HEVC).
- 2026-10-10 — Onglets sans View Transition (les barres givrées perdent leur flou) : l'écran attend d'être prêt (`ready`, 250 ms au plus), l'ancien se fond dans un calque fixe ; cartes mises à jour sur place (`reconcile`/`cardSig`). Navigation : View Transitions (glissement à droite), onglets qui reviennent au bas de l'historique ; le glissement depuis le bord est celui d'iOS, pas redessiné.
- 2026-10-10 — Sous-titres d'une conversion dans le flux HLS (`appleStream` → `SubtitleMethod=Hls`), liste principale par `/Mira/hls/…` — AirPlay, un seul jeu de pistes, WebVTT de Jellyfin datés pour des segments TS. ASS/SSA demandés en `.vtt` (profils `External`), partout : sinon incrustés en réencodant ; mise en forme perdue.
- 2026-10-10 — Téléphone : une carte du guide, étapes cochées, « Tout préparer » (une autorisation de Windows), QR code à l'adresse Tailscale quand elle est prête (elle marche aussi à la maison) — demandé par l'utilisateur.
- 2026-10-10 — Pare-feu lu et ouvert par le guide, maison et Tailscale, avec ou sans service (sans service : seules les règles de l'invite de Windows ; Tailscale est privé, la box souvent publique) : blocages privés de ces profils (pas supprimés), puis règle « Mira - Jellyfin », domaine et privé seulement (SEC-03, option recommandée, carte de décision restée sans réponse) ; réseau public passé en privé seulement par « Passer en privé ».
- 2026-10-09 — Service : `sc config start= auto` (différé gardé), `sc failure` (trois relances puis rien) + `failureflag 1` (pas `AppExit Restart` : un arrêt voulu reste un arrêt) , règles de pare-feu `localsubnet` et `100.64.0.0/10` pour `jellyfin.exe` (l'installateur de Jellyfin n'en ajoute aucune pour son service).
- 2026-10-11 — Élévation (SEC-04) : Windows PowerShell de System32 avec un script fixe, jamais `Mira.exe` (son dossier est modifiable sans droits).
- 2026-10-14 — Conversions par la carte graphique (Réglages Windows, Jellyfin sur ce PC, admin) : seul `HardwareAccelerationType` (+ `EnableHardwareEncoding`) change, décodage laissé au défaut de Jellyfin (H.264, VC-1) ; chaque carte (NVIDIA, Intel, AMD) essayée sur une vraie conversion (`Videos/{id}/stream.ts`, 500 = échec, vérifié sur 12.1), sinon réglage remis — demandé par l’utilisateur. Revérifiée (`GpuRecheck`, `MainWindow.GpuRecheck.cs`) quand la version de Jellyfin ou un pilote change (empreinte `GpuCheckedFor`, notée aussi par un essai réussi des réglages), jamais pendant une lecture, toutes les 30 min ; deux échecs de suite (`GpuFailures`) = processeur et avis.
- 2026-10-14 — Minuterie (web, Windows, Mac ; `SleepTimer` et `sleep.js`, cas communs `tests/fixtures/sleep.json`) : horloge murale, pause une seule fois, « fin de l’épisode » = pas d’épisode suivant ; effacée à la fermeture du lecteur ; sur iPhone et iPad choisie sur la fiche (le lecteur d’Apple n’a pas les menus de Mira).
- 2026-10-14 — « En ce moment sur Jellyfin » (Windows, `Viewers`, Réglages → Jellyfin, relu toutes les 5 s) ; « Arrêter » = `Sessions/{id}/Playing/Stop`, reçu par Mira web seulement pendant la lecture : `remote.js` déclare `supportsMediaControl` et ouvre `socket?ApiKey=…&deviceId=…` (`api_key` refusé par 12.1), répond aux `ForceKeepAlive` ; base pour SyncPlay. Mira web (2026-10-15, administrateur seulement) : `#/en-ce-moment` (`views/now.js`, textes de `viewers.js`, cas communs `tests/fixtures/viewers.json`), relu toutes les 5 s seulement à l’écran, « Arrêter » confirmé par une feuille.
- 2026-10-14 — Nouveaux épisodes (Windows, `NewEpisodes`, `Services/Toasts.cs`) : séries suivies = favori ou `PlayedPercentage` > 0 ; marque = `DateCreated` de Jellyfin du plus récent vu (`EpisodesSeenFor`/`EpisodesSeenUntil`), premier passage = marque seule ; regard 90 s après un `LibraryChanged`, et toutes les 30 min. Notifications Windows sous l'AUMID enregistré par `WindowsIdentity.Register` (profil de validation : aucune). Mira web (notifications web = HTTPS) : avis à l'ouverture (`news.js`, règles dans `new-episodes.js`, cas communs `tests/fixtures/new-episodes.json`), repère `mira.home.<user>.episodes` (effacé à la déconnexion, jamais écrit sans stockage), pas sur le lecteur, une invitation ni une feuille ouverte (« Nouveau dans Mira »), de nouveau après 15 min en arrière-plan.

## Fragile / ne pas toucher sans raison
### Mira web, iOS, WebKit
- Icône de l’écran d’accueil (`img/*.png`) : iOS 18+ assombrit le fond clair d’un raccourci web en apparence sombre et n’accepte aucune variante sombre : icône sombre (glyphe de `mark.svg` en `#f5f5f7`, fond `#252528` → `#0d0d0f`, pleine page). iOS garde l’icône vue à l’ajout.
- iOS en HTTP local : pas de service worker, `crypto.randomUUID`, presse-papiers ni Wake Lock.
- Lecteur d'Apple : `<track>` ajoutées **avant** `src` ; changements de pistes suivis seulement en plein écran et 1,5 s après le chargement ; plein écran sans toucher sur iPhone après le premier geste, avec toucher sur Mac ; sur un changement de source, `webkitpresentationmodechanged` peut arriver après la nouvelle demande de plein écran (fermeture pendant l'épisode suivant : `presentation()`, `switchFrom`).
- WebKit : régler une piste sur son mode actuel ne compte pas ; une piste jamais réglée est choisie par WebKit ; un choix dans le menu d'Apple change les réglages de l'iPhone. `:active` gardé pendant un défilement : appuis par `press.js` (`.pressed`). `<track kind="forced">` : Safari seulement.
- Commandes masquées (`.player.idle`) : `pointer-events: none`, un test les réaffiche avant de cliquer. `.player.fitted` : Safari place les sous-titres en bas du cadre.
- Erreur de flux : attendre le serveur seulement si `ping()` échoue (sinon boucle sur une erreur 500).
- View Transitions : changement d'écran dans un rappel différé ; `enter()` et ce qui touche l'écran affiché vont dans `swap`. Image `loading=lazy` d'un écran caché jamais chargée : `ready` ne décode que `img[loading="eager"]`. Carte gardée par `reconcile` : ses menus lisent `card.item`. Pas de `content-visibility` sur les cartes (rogne `.holding` et le focus). Grille : pages de 60, actualisée par sa première page (`GRID_FIELDS`).
- Stockage bloqué : lire `localStorage`/`sessionStorage` lève ; `sessionStorage` par `temp` (`session.js`) ; rechargement gardé par une note seulement si `temp.set` a réussi, sinon boucle.
- Quick Connect (connexion par code) : désactivé, Jellyfin répond 401 à `QuickConnect/Authorize` et `Initiate` ; vérifier `QuickConnect/Enabled` avant d'autoriser (sinon 401 = fin de session, web et Windows/Mac). Code oublié par Jellyfin = 404 sur `Connect`.
- Jeton : envoyé seulement après `trustServer()` (dans `request()`) ; un `fetch` direct qui le porte l'appelle d'abord (`bitrateTest`) ; appels publics `token: null`. Clé de compte dans `localStorage` : `mira.home.`, `mira.library.` ou `ACCOUNT_SETTINGS`, pour être effacée à la déconnexion.
- CSP sans `'unsafe-inline'` : jamais d'attribut `style=` (HTML, `innerHTML`, `setAttribute('style')`, `cssText`), seulement `h(…, { style })` ou `el.style.x` ; le `<style>` d'`index.html` est permis par son empreinte (`ContentPolicy`).
- Débit « Automatique » : mesure gardée une heure ; Tailscale n'est pas « la maison » (contrairement à `isLocalHost`, pour l'avertissement HTTP).
- Modules importés par Node (`i18n.js`, `stream.js`, `timeline.js`, `presentation.js`, `tracks.js`, `sleep.js`, `sync.js`, `viewers.js`, `torlink.js`, `releases.js`, `owned.js`, `seasons.js`, `identify.js`, `dom.js`, `whats-new.js`, `new-episodes.js`, `choices.js`) : rien du navigateur au chargement ; tests hors de `src/Mira.Web` (tout y est servi). Syntaxe : `node --experimental-default-type=module --check` (sans l'option, une redéclaration passe).
- Extension : héritée de `BasePlugin<BasePluginConfiguration>` (sinon version nulle, « en défaut ») ; `WebFiles.Types` connaît chaque extension servie (`.mjs` manquant = page du QR code cassée ; type inconnu → `Unserved`, test en échec). Avec `MIRA_WEB_DIR`, page non gardée : « serveur éteint » se teste avec l'extension compilée.

- Fournisseur de sous-titres : ids sans `_` (Jellyfin préfixe `<md5 du nom>_` et coupe au premier) ; `IMediaSourceManager.GetMediaStreams(Guid)` a changé de type de retour en 12.x : appelé par réflexion (sinon `MissingMethodException`) ; le téléchargeur automatique de Jellyfin prend le premier résultat et retélécharge à chaque passage (`.fre.0.srt`, `.fre.1.srt`) : `AlreadyHas` (fichier à côté, cache 2 h). ; pendant l'analyse, Jellyfin demande les sous-titres d'un épisode avant de l'avoir numéroté : saison et numéro repris de la requête ou du nom du fichier (`Numbers`, et dans `SubtitleMatch.Score`), sinon rien d'automatique (sans eux, une source répond pour toute la série).

### Windows : app
