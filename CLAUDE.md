# Mira

## Objectif
Client Jellyfin « cinéma » : une app Windows native avec mpv intégré, sa version Mac, et Mira web pour iPhone, iPad et
Android, servie par le serveur Jellyfin lui-même. Pour un particulier qui regarde sa bibliothèque chez lui et ailleurs.

## Stack
- .NET 10 (`global.json` : SDK 10.0.100, roll forward dans 10.0), C#. L'extension Jellyfin reste en `net8.0` (Jellyfin 10.9 et 10.10 tournent en .NET 8).
- Windows : WPF (`src/Mira.Desktop`), lecteur libmpv. Mac : Avalonia (`src/Mira.Mac`), libmpv embarquée, `.dmg`, macOS 15 ou plus (après la 0.7.4).
- Code commun : `src/Mira.Core`. Mira web : HTML, CSS, modules JS sans build (`src/Mira.Web`), vendorisés : hls.js, qrcode-generator.
- Extension : `src/Mira.Jellyfin`, compilée contre Jellyfin.Controller 10.9.11, chargée par Jellyfin 12.1. Serveur : Jellyfin 10.9 ou plus.

## Architecture (détail : `docs/ARCHITECTURE.md`, sécurité : `SECURITY.md`, tests : `docs/TESTS.md`)
- `src/Mira.Core/` : `JellyfinClient` (API, `InstallWebAppAsync`), `MiraWeb`/`MiraWebRelease` (dépôt, QR code, vérification), `PlayerText`, `WhatsNew.json`/`WhatsNew.cs`, `Updates/`, `JellyfinStartup` (plan et script élevé), `JellyfinFirewall` (jugement du pare-feu), `PhoneSetup` (étapes du téléphone), `TorLink/`.
- `src/Mira.Desktop/` : `MainWindow.*.cs` par sujet (`Guide` = carte « Mira sur ton téléphone »), harnais dans `Checks/` (lancés par `RunRequestedCheckAsync`, absents des paquets : `-p:MiraValidation=false`), `Services/JellyfinAutostart.cs` (lit le service et le pare-feu sans droits, lance le script élevé).
- `src/Mira.Jellyfin/` : `WebController` sert `/Mira`, `WebFiles` les fichiers intégrés (révision = empreinte), `HlsController` `/Mira/hls`, `ContentPolicy`, `TorLinkController`/`TorLinkRelay` `/Mira/torlink` (administrateurs).
- `src/Mira.Web/` : `js/app.js` (routes `#/...`, bandeau « serveur injoignable », mise à jour par révision, « Nouveau dans Mira »), `api.js`, `views/*`, `player/` (`player.js` lecteur d'Apple ou commandes de Mira, `stream.js` cascade et adresses, `timeline.js` passages et trickplay, `presentation.js` plein écran d'Apple, `profile.js`, `video.js` `<video>` partagée et `appleNative()`, `tracks.js` pistes).
- Tests : `tests/Mira.Core.Tests` (sans WPF, partout, Linux en CI), `tests/Mira.Tests` (les mêmes puis l'app Windows), `tools/web/unit` (Node). Exécutables d'assertions, pas `dotnet test` : `--filter <texte>`, `--list`, un échec n'arrête pas les suivants.
- `tools/` : `release.ps1`, `package.ps1`, `publish.ps1` (`dist/Mira`), `mac/package.sh`, `web/`. Workflows : `ci.yml` (Linux + Windows), `mac.yml`, `web.yml` (Chromium et Safari).
- Mira web : téléphone → `http://<serveur>:8096/Mira` → extension → app → API Jellyfin ; Safari lit le fichier tel quel, sinon HLS fMP4 (H.264 d'abord).

## Commandes
- Build : `dotnet restore Mira.sln --configfile NuGet.Config` puis `dotnet build Mira.sln -c Release --no-restore`. Mac hors de `Mira.sln` : `dotnet build src/Mira.Mac/Mira.Mac.csproj -c Release` (compile aussi sous Linux). Démo : `dotnet run --project src/Mira.Desktop/Mira.Desktop.csproj -- --demo --data .artifacts/dev-profile`.
- Tests : `dotnet run --project tests/Mira.Tests/Mira.Tests.csproj -c Release --no-build` (Windows) ; partout `dotnet run --project tests/Mira.Core.Tests/Mira.Core.Tests.csproj -c Release` ; `node --test tools/web/unit/*.test.mjs`.
- Mira web : `tools/web/package.sh <x.y.z> [base]` → `dist/web/` ; médias `tools/web/media.sh <dossier> [formats]` ; Jellyfin neuf `node tools/web/setup.mjs <serveur> <médias> <user> <mdp> [manifeste]` ; Chromium (108 points, 110 avec `MIRA_STOP`/`MIRA_START`, commandes qui arrêtent et relancent Jellyfin ; lecteur d'Apple simulé) `PLAYWRIGHT=<.../playwright/index.mjs> node tools/web/check.mjs <url /Mira/> <user> <mdp> "Courte Web" <dossier>` ; Safari (Mac, `safaridriver -p 4444`, 26 points, 34 avec `MIRA_FORMATS=1`) `node tools/web/safari.mjs <url /Mira/> <user> <mdp> <dossier>` ; sans recompiler : Jellyfin avec `MIRA_WEB_DIR=<src/Mira.Web>`.
- Conteneur cloud : Jellyfin par Docker (`dockerd &`, `jellyfin/jellyfin:12.1.20260915-010956`, `--network host`) ; SDK .NET de Microsoft depuis les `.deb` de packages.microsoft.com (`debian/12` : ni jammy ni noble n'ont .NET 10 ; builds.dotnet.microsoft.com bloqué), `dpkg-deb -x`, puis `-p:EnableWindowsTargeting=true` (compile seulement).
- CI d'une branche : `web.yml` et `ci.yml` par `workflow_dispatch` (`actions_run_trigger`) ; journaux : `get_job_logs` (le proxy refuse les zips).
- Defender et compilation reproductible : `defender.yml` par `workflow_dispatch` (`commit`, `release=vX.Y.Z`) compile sur un runner propre, le fait scanner par le Defender du runner (cloud activé par `Set-MpPreference`, sinon aucun verdict « !ml ») et compare avec le zip publié ; `node tools/compare-assemblies.mjs <a.dll> <b.dll>` compare deux compilations d'un même commit partie par partie (corps des méthodes, tas de métadonnées, ressources) : un diff d'octets ne vaut rien, une chaîne plus longue décale tout. Deux compilations honnêtes diffèrent par le MVID, les versions des outils du SDK dans `#Blob`, le hachage du générateur de regex, `\` ou `/` dans les noms de ressources selon l'OS ; `Version` informationnelle = `x.y.z+<sha du commit>`, l'empreinte change donc à chaque commit, même sans changement de code.
- Audits : restauration en échec sur faille NuGet haute ou critique, même transitive (`NuGetAuditMode=all`) ; `dotnet list package --vulnerable --include-transitive` (`EnableWindowsTargeting=true` sous Linux) ; `dotnet format whitespace . --folder --verify-no-changes` (CI) ; eslint 9 et shellcheck depuis le scratchpad.
- Publication (PC de l'utilisateur, où est la clé) : `git checkout main; git pull --ff-only; .\tools\release.ps1`. Exige releases immuables, gh, clé (`Mira.Release check-key`), Inno Setup, arbre propre, `main` = GitHub, `ci.yml` vert sur ce commit, tag absent ; brouillon `--draft --target <commit>`, lance `web.yml`/`mac.yml` sur `main` (`-f release=vX.Y.Z -f commit=<sha>`), prend leurs artefacts (`Mira-mac-arm64`, `Mira-web-release`), signe (`manifest --others`), compare le `digest` des 12 fichiers, publie, vérifie `immutable`. `-DryRun` laisse le brouillon ; `-SkipBuild` reprend les paquets du même commit.

## Conventions
- Avertissement = erreur partout (`Directory.Build.props`) ; NU1900-NU1902 (faille basse ou moyenne, source d'avis injoignable) restent des avertissements. Dependabot (`.github/dependabot.yml`) : NuGet et actions, mensuel, groupé, 7 jours de recul, pas de majeure NuGet ni de `Jellyfin.Controller`.
- `.editorconfig` décrit le style réel (plusieurs instructions par ligne, initialiseurs compacts, `case` en bloc non indenté). Le formateur met quand même un bras de `switch` et un membre de `with { }` multiligne par ligne : pas d'option pour ça. Les formateurs des SDK 8 et 10 ne s'accordent pas sur le corps d'un `else foreach` sans accolades : des accolades.
- Interface et docs en français, en tutoyant ; messages de commit en anglais.
- Fins de ligne : CRLF pour `.cs`, `.xaml`, `.axaml` ; LF pour `.sh`, `.md`, `.yml`, `.json`, `.js`, `.mjs`, `.css`, `.html`, `.webmanifest` (`.gitattributes`).
- Chaque version a son entrée dans `WhatsNew.json` (résumé ≤ 100 caractères, 2 à 5 points, icônes dessinées par Mira) : le test « Nouveautés : bienvenue… » le vérifie. `"web": true` sur un point que Mira web montre aussi (« Nouveau dans Mira », une fois sur le téléphone, texte valable pour lui) ; sans point marqué, le téléphone ne montre rien de cette version.
- `CHANGELOG.md` : section « Non publié » en haut, datée à la publication.
- Version : `<Version>` dans les csproj Desktop, Mac et Jellyfin ; ne la change qu'à la préparation d'une release demandée.
- Les PR se fusionnent en rebase (depuis la session, à la demande de l'utilisateur) ; la publication se fait depuis son PC.
- Windows : palette unique dans `Themes/Cinema.xaml` (fonds `Bg` à `LineStrong`, encres `Text` à `Dim`, `OnAccent`, états `Success`/`Warning`/`Danger`, calques `Hairline`, `Menu`, `Toast`, `Sheet`…), noms et neutres de Mira web ; XAML par `{StaticResource}` (`Muted`, `Faint`, `FocusRing` en `DynamicResource` : contraste élevé), code par `Palette.Get("Nom")`. Jamais une couleur écrite, sauf dégradés, contenu (démo, affiches, marque) et animations ; `Dim` jamais pour du texte (test de contraste).
- Mira web : design sombre (tokens dans `:root` de `app.css`), police Nunito Sans auto-hébergée, icônes Phosphor (`js/icons.js`). Taille de texte en `calc(Npx * var(--text))` (réglage « Taille du texte »), sauf libellés des onglets et du lecteur.
- Un test sans WPF va dans `tests/Mira.Core.Tests` (un fichier de Desktop sans WPF y est lié par son csproj) ; un test seulement Windows (chemins, liens physiques, DPAPI) dans `tests/Mira.Tests/Program.cs`. Code commun Windows/Mac dans Core (`IconPaths`, `MpvLists`, `MpvClient`, `PlaybackSession`, `SkipPlanner`) ; état du catalogue Windows dans `Catalog`, rangement TorLink dans `TorLinkPlacement`.

## Décisions (et pourquoi)
- 2026-10-08 — Mac en Avalonia avec libmpv embarquée — partage `Mira.Core` et le lecteur de Windows.
- 2026-10-09 — iPhone par une app web servie par une extension Jellyfin — ni App Store, ni compte Apple, ni AltStore, gratuit.
- 2026-10-11 — Dépôt de l'extension = `releases/download/vX.Y.Z/jellyfin-manifest.json` de la version de Mira pour Windows, vérifiée par sa signature ; releases en brouillon, signées en dernier, publiées d'un coup, immuables — Jellyfin ne vérifie qu'un MD5 fourni par la même release (SEC-02).
- 2026-10-09 — Une seule `<video>` partagée, débloquée au premier toucher (iOS n'autorise le son qu'après un geste) ; épisode suivant dans le même lecteur (`history.replaceState`) : retirer la `<video>` quitte le plein écran.
- 2026-10-09 — Profil d'appareil : H.264 avant HEVC en HLS — conversion le plus souvent sans réencodage.
- 2026-10-09 — iPhone et iPad : lecture seulement dans le plein écran d'Apple (pas de `playsinline`), demandé par l'utilisateur ; audio et sous-titres choisis sur la fiche (le menu d'Apple ne change pas l'audio d'une conversion).
- 2026-10-09 — `/Mira/` gardée un mois par le téléphone, révision vérifiée à chaque démarrage — s'ouvre PC éteint et attend le serveur ; pas de service worker en HTTP.
- 2026-10-10 — Dynamic Island : défaut d'iOS pour les apps de l'écran d'accueil, rien dans la page n'y change rien ; seul levier, la session audio `ambient` (seule mêlable, coupée par le mode silencieux) : option « Masquer la Dynamic Island », iPhone seulement, qui le dit.

## Fragile / ne pas toucher sans raison
### Mira web, iOS, WebKit
- Icône de l’écran d’accueil (`img/*.png`) : iOS 18+ assombrit le fond clair d’un raccourci web en apparence sombre et n’accepte aucune variante sombre : icône sombre (glyphe de `mark.svg` en `#f5f5f7`, fond `#252528` → `#0d0d0f`, pleine page). iOS garde l’icône vue à l’ajout.
- iOS en HTTP local : pas de service worker, `crypto.randomUUID`, presse-papiers ni Wake Lock.
- Lecteur d'Apple : `<track>` ajoutées **avant** `src` ; changements de pistes suivis seulement en plein écran et 1,5 s après le chargement ; plein écran sans toucher sur iPhone après le premier geste, avec toucher sur Mac ; sur un changement de source, `webkitpresentationmodechanged` peut arriver après la nouvelle demande de plein écran (fermeture pendant l'épisode suivant : `presentation()`, `switchFrom`).
- WebKit : régler une piste sur son mode actuel ne compte pas ; une piste jamais réglée est choisie par WebKit ; un choix dans le menu d'Apple change les réglages de l'iPhone. `:active` gardé pendant un défilement : appuis par `press.js` (`.pressed`). `<track kind="forced">` : Safari seulement.
- Commandes masquées (`.player.idle`) : `pointer-events: none`, un test les réaffiche avant de cliquer. `.player.fitted` : Safari place les sous-titres en bas du cadre.
- Erreur de flux : attendre le serveur seulement si `ping()` échoue (sinon boucle sur une erreur 500).
- View Transitions : changement d'écran dans un rappel différé ; `enter()` et ce qui touche l'écran affiché vont dans `swap`. Image `loading=lazy` d'un écran caché jamais chargée : `ready` ne décode que `img[loading="eager"]`. Carte gardée par `reconcile` : ses menus lisent `card.item`. Pas de `content-visibility` sur les cartes (rogne `.holding` et le focus). Grille : pages de 60, actualisée par sa première page (`GRID_FIELDS`).
- Stockage bloqué : lire `localStorage`/`sessionStorage` lève ; `sessionStorage` par `temp` (`session.js`) ; rechargement gardé par une note seulement si `temp.set` a réussi, sinon boucle.
- Quick Connect (connexion par code) : désactivé, Jellyfin répond 401 à `QuickConnect/Authorize` et `Initiate` ; vérifier `QuickConnect/Enabled` avant d'autoriser (sinon 401 = fin de session, web et Windows/Mac). Code oublié par Jellyfin = 404 sur `Connect`.
- Jeton : envoyé seulement après `trustServer()` (dans `request()`) ; un `fetch` direct qui le porte l'appelle d'abord (`bitrateTest`) ; appels publics `token: null`. Clé de compte dans `localStorage` : `mira.home.`, `mira.library.` ou `ACCOUNT_SETTINGS`, pour être effacée à la déconnexion.
- CSP sans `'unsafe-inline'` : jamais d'attribut `style=` (HTML, `innerHTML`, `setAttribute('style')`, `cssText`), seulement `h(…, { style })` ou `el.style.x` ; le `<style>` d'`index.html` est permis par son empreinte (`ContentPolicy`).
- Débit « Automatique » : mesure gardée une heure ; Tailscale n'est pas « la maison » (contrairement à `isLocalHost`, pour l'avertissement HTTP).
- Modules importés par Node (`stream.js`, `timeline.js`, `presentation.js`, `tracks.js`, `sleep.js`, `sync.js`, `viewers.js`, `torlink.js`, `dom.js`, `whats-new.js`, `new-episodes.js`, `choices.js`) : rien du navigateur au chargement ; tests hors de `src/Mira.Web` (tout y est servi). Syntaxe : `node --experimental-default-type=module --check` (sans l'option, une redéclaration passe).
- Extension : héritée de `BasePlugin<BasePluginConfiguration>` (sinon version nulle, « en défaut ») ; `WebFiles.Types` connaît chaque extension servie (`.mjs` manquant = page du QR code cassée ; type inconnu → `Unserved`, test en échec). Avec `MIRA_WEB_DIR`, page non gardée : « serveur éteint » se teste avec l'extension compilée.
### Jellyfin et médias de test
- En démarrage, Jellyfin 12 répond à `System/Info/Public` (camelCase) et 503 au reste : seul `System/Ping` prouve qu'il est prêt ; ce n'est pas un « serveur étranger ».
- `System/Restart` redémarre Jellyfin dans le même processus : une extension réinstallée sous un numéro déjà chargé garde l'ancien code (même identité d'assembly) ; en test, `docker restart`.
- `EnableSubtitlesInManifest` n'est lu que pour `live.m3u8` : pour un film, `SubtitleMethod=Hls` (sans `SubtitleStreamIndex`, tout en `DEFAULT=NO`) ; `SubtitleMethod=Encode` pour -1 n'est pas une incrustation. ASS/SSA jamais convertis par le profil (`SupportsSubtitleConversionTo`).
- Segments HLS TS à 10 s, fMP4 à 0, WebVTT HLS à `MPEGTS:900000` en dur : hls.js s'en moque, le lecteur d'Apple non.
- SyncPlay de 12.1 : un WebSocket fermé finit la session, et un groupe vide disparaît en moins d'une seconde (iPhone dans Messages) ; un appareil qui rejoint (même groupe) est un nouveau venu : `PlayQueue` du même `PlaylistItemId` et groupe en attente de lui, à répondre par `Ready` (lecteur ouvert) ou `SetIgnoreWait` (fermé), sinon tous restent en pause. Dans Chromium, `setOffline` ne ferme pas un WebSocket ouvert : `check.mjs` le coupe par `routeWebSocket`.
- Jellyfin 12.1 : `allowVideoStreamCopy=false` écrit seulement pour HLS, `VideoCodec=` même quand il copie (`copiesVideo` lit `TranscodeReasons`) ; ne lit plus `BreakOnNonKeyFrames`, `MinSegments`, ni les étiquettes de codec ; ne reconvertit pas un VP9 de niveau inconnu (la cascade Chromium part d'un H.264).
- Tests : `-shortest` de ffmpeg compte les sous-titres (durée par `-t`) ; `.srt` sans accents (Jellyfin devine mal l'encodage d'un fichier d'une ligne) ; Safari peut attendre un geste (partir du bouton « Lecture ») ; Chromium de Playwright sans H.264 ni AAC (WebM) ; `MinResumeDurationSeconds` à 1 (`setup.mjs` ; 5 min par défaut) ; Mac sans `md5sum` ni `base64 -w` ; la VM Mac refuse le HEVC 10 bits HDR10 copié.
### Windows : pare-feu, service, élévation
- Pare-feu : un blocage l'emporte sur toute autorisation ; l'invite « Autoriser l'accès » bloque les profils non cochés. `HNetCfg.FwPolicy2` en `dynamic` (IDispatch par nom : une interface `ComImport` mal ordonnée appellerait une autre méthode, en administrateur) ; propriétés indexées `policy.FirewallEnabled[profil]`. Règle de Mira jugée sur son contenu (`JellyfinFirewall.MiraRule`), profils `JellyfinStartup.RuleProfiles` ; jugement des deux origines dans Core (`JellyfinFirewall.Phones`, testable sous Linux).
- Profil des cartes : `MSFT_NetConnectionProfile` (WMI, `WbemScripting.SWbemLocator` en `dynamic`, sans droits) ; `InterfaceAlias` = `NetworkInterface.Name`. « Passer en privé » : `ApplyAsync(port, privateNetwork: true)`, `Put_(1)` dans le script, jamais un domaine, refus relu = `KeptPublic`.
- « Tout préparer » : une étape `ToDo` doit être faisable par Mira (sinon l'autorisation revient à chaque clic) ; ce que Mira ne change pas (tout bloquer, règle sans programme, programme introuvable) est `Yours` ; Jellyfin muet (`System/Ping`) : rien n'est conclu.
- Script élevé : Windows PowerShell 5.1, `-EncodedCommand`, ni `??` ni ternaire, aucune cmdlet ni module (`$PSModuleAutoLoadingPreference = 'None'`), textes en base64, ligne ≤ 30 000 caractères (`MaximumArguments`). Tests Windows par le même script sans élévation ; sous Linux, `pwsh` avec de faux `sc.exe`/`netsh.exe` dans le dossier courant (`[Environment]::SystemDirectory` vide).
- `sc failure … restart/…/restart/60000//0` : Windows répète la dernière action, la quatrième, vide, arrête les relances (test CI sur `FailureActions`).
- Network Service : lecture sur `Films`, `Séries`, `Animes` seulement (traverser suffit) ; 0.7.4 et avant l'avaient sur la racine, retrait dans `docs/INSTALLATION.md`.
### Windows : app
- Gestionnaire global (`App.xaml.cs`) : fenêtre ouverte → `Handled = true` et message ; avant `Show()` ou pendant la fermeture (`IsClosing`) → `Shutdown(1)`, sinon un processus sans fenêtre garde le mutex. `Window_Closing` (et `OnClosing` du Mac) : chaque étape dans `Attempt` (`errors.log`), fermeture dans `finally`. `--windows-check` écrit `failure.txt` même sans fenêtre. Mac : `Dispatcher.UIThread.UnhandledException`, même règle, `--self-check` laissé planter.
- Arrêt de Windows ou Restart Manager : `SessionEnding` puis fermeture sans attente ; ce qui doit survivre va dans `KeepForNextStart` (synchrone, avant le premier `await` de `Window_Closing`) et `SessionEnding` (« stop » en file, 1,5 s au plus).
- `InstanceActivation` : canal hors du fil de l'interface, créé juste après le mutex (sinon faux « déjà ouvert ») ; réponses `shown`/`starting`/`closing` (la relance attend le mutex puis refait les contrôles).
- Fenêtre : `ScreenFit.Place` en pixels physiques à `SourceInitialized` (déplacement, puis taille) ; `Maximized` après, jamais dans le constructeur. Snap Layouts : `SnapHook` (`HTMAXBUTTON`) ajouté après le crochet de `WindowChrome` ; WPF ne voit plus la souris sur ce bouton.
- Narrateur : le style `Button` lie `AutomationProperties.Name` au texte du contenu (`Accessible.ContentName`) ; une icône seule a son nom ; `CaptureAsync` échoue sur un contrôle visible sans nom (`AssertNamed`). `System.Windows.Readability` existe : la classe de Core est `Legibility`.
- Délai `HttpClient` (12 s) = `TaskCanceledException`, jeton de l'appelant intact : ignorer une annulation seulement `when (ct.IsCancellationRequested)` avec le jeton pris au départ (`_connectionLifetime` change avec le compte), sinon un serveur muet ne donne aucun avis ; une actualisation `quiet` l'ignore aussi tant que la page montre quelque chose. `IsExpected`/`Errors.Expected` → `ExpectedErrors.Are` : seule `UserInputException` est une `ArgumentException` attendue, toute autre va au gestionnaire global.
- Réglages illisibles : copie `settings.json.bad-<date>` (Windows et Mac) ; `TrySaveSettings` ne lève jamais ; masquer `SettingsOverlay` appelle `AutoSaveSettings()` d'abord ; avis du démarrage par `AddNotice`. `FileShare.None` n'est que consultatif hors de Windows.
- `LibraryStore` : `CreateSchema`, `quick_check(1)` et `Prune` dans le même `try` ; base mise de côté sur 11, 26, 266 (`IOERR_READ`) et 8458 (`IOERR_CORRUPTFS`) ; disque plein, verrou ou lecture seule remontent. `quick_check` décrit en texte sans lever (sauf page 1). EIO simulable sous Linux : LD_PRELOAD sur `pread64`. Pas de `:memory:`. Cache = bonus (`TryCache`) ; `Save` saute une page identique : toute écriture de `cache` passe par `Save`.
- Images : décodées à la taille affichée × échelle (`Artwork.Pixels`, largeur dans la clé) ; la grille charge à l'approche (`LoadVisibleArtwork`) : une capture attend `ImageReady`. Carrousel à 30 Hz arrêté en pause (`UpdateHeroClock` à chaque nouvelle cause). `SyncService` dort sans envoi (`Wake()`) ; « Hors connexion » vient de `_offlineSince`.
- Veille : `_fileOpen` de `Load` à END_FILE ; rouvrir le flux saute la fin de l'ancien (`_skipEnds`) ; une fin pendant la veille ou avant la réponse de Jellyfin n'est jamais une fin de titre ; un flux rouvert qui échoue n'est jamais « vu ».
- Connexion : `ServerAddress` refuse un HTTP après un certificat refusé seulement pour un nom d'Internet (adresse finale) ; `ExposesPasswordAsync` compte toujours un nom d'Internet comme Internet. Hors Windows, TLS vers un port HTTP = `AuthenticationException`. Dans le conteneur, .NET ignore les CIDR de `NO_PROXY`.
- Déconnexion : session locale effacée, puis `Sessions/Logout` (3 s) ; `_signingOut` ; caches d'un compte nommés dans `AccountData` ; `LibraryStore.Delete` vide le pool SQLite d'abord.
