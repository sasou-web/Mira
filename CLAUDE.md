# Mira

## Objectif
Client Jellyfin « cinéma » : une app Windows native avec mpv intégré, sa version Mac, et Mira web pour iPhone, iPad et
Android, servie par le serveur Jellyfin lui-même. Pour un particulier qui regarde sa bibliothèque chez lui et ailleurs.

## Stack
- .NET 10 (`global.json` : SDK 10.0.100, roll forward dans 10.0), C#. L'extension Jellyfin reste en `net8.0`.
- Windows : WPF (`src/Mira.Desktop`), lecteur libmpv. Mac : Avalonia (`src/Mira.Mac`), libmpv embarquée, `.dmg`, macOS 15 ou plus (après la 0.7.4).
- Code commun : `src/Mira.Core` (client Jellyfin, synchro, mises à jour signées, nouveautés, TorLink).
- Mira web : HTML, CSS et modules JS sans étape de build (`src/Mira.Web`), vendorisés : hls.js, qrcode-generator.
- Extension Jellyfin : `src/Mira.Jellyfin`, compilée contre Jellyfin.Controller 10.9.11 et chargée par Jellyfin 12.1.
- Jellyfin 10.9 ou plus récent côté serveur.

## Architecture
- `src/Mira.Core/` → `JellyfinClient.cs` (API, dont `InstallWebAppAsync`), `MiraWeb.cs` (dépôt, adresse du QR code), `PlayerText.cs` (noms des pistes en français), `WhatsNew.json` et `WhatsNew.cs` (nouveautés, texte de la page de release), `Updates/` (mises à jour signées).
- `src/Mira.Desktop/` → app Windows ; harnais de contrôle (`--visual-check`, `--player-check`…) dans `Checks/`, lancés par `RunRequestedCheckAsync` ; `MainWindow.Guide.cs` contient la carte « Mira sur ton téléphone » (étapes de `src/Mira.Core/PhoneSetup.cs`, « Tout préparer », QR code).
- `src/Mira.Mac/` → app Mac.
- `src/Mira.Jellyfin/` → `WebController.cs` sert `/Mira` ; `WebFiles.cs` sert les fichiers intégrés à la DLL, versionnés par une empreinte.
- `src/Mira.Web/` → `index.html`, `app.css`, `js/app.js` (routes en `#/...`, bandeau « serveur injoignable », mise à jour par révision), `js/api.js`, `js/views/*`, `js/player/` (`player.js` = lecteur d'Apple ou commandes de Mira, `stream.js` = cascade de secours, adresses des flux et débit, `timeline.js` = passages, épisode suivant, trickplay, `presentation.js` = ouverture et fermeture du lecteur d'Apple, `profile.js` = profil d'appareil, `video.js` = `<video>` partagée et `appleNative()`, `tracks.js` = noms et choix des pistes).
- `src/Mira.Core/JellyfinStartup.cs` + `src/Mira.Desktop/Services/JellyfinAutostart.cs` → Jellyfin joignable par le téléphone (pare-feu pour la maison et Tailscale, service, relance) ; Mira décide sans droits (`JellyfinAutostart.Plan`), Windows PowerShell de System32 exécute avec l'élévation un script fixe (`JellyfinStartup.Script`), une seule autorisation. `src/Mira.Core/JellyfinFirewall.cs` juge les règles du pare-feu.
- `tests/Mira.Core.Tests/` → tests sans WPF (net10.0, un fichier par thème, aussi sous Linux en CI) ; `tests/Mira.Tests/` compile les mêmes fichiers puis ceux de l'app Windows. Exécutables d'assertions (pas `dotnet test`) : un échec n'arrête pas les suivants, bilan à la fin, `--filter <texte>`, `--list`.
- `tools/` → `release.ps1` (publication en une commande), `package.ps1` (paquets Windows signés), `publish.ps1` (copie locale `dist/Mira`), `mac/package.sh`, `web/` (empaquetage et contrôles de Mira web).
- `.github/workflows/` → `ci.yml` (Windows), `mac.yml` (Mac, `.dmg` joint aux releases), `web.yml` (Chromium et Safari, extension et manifeste joints aux releases).
- Flux de Mira web : téléphone → `http://<serveur>:8096/Mira` → extension → app web → API Jellyfin. Lecture : Safari lit le fichier tel quel, sinon Jellyfin convertit en HLS fMP4 (H.264 d'abord).

## Commandes
- Windows : `dotnet restore Mira.sln --configfile NuGet.Config`, puis `dotnet build Mira.sln -c Release --no-restore`.
- Tests : `dotnet run --project tests/Mira.Tests/Mira.Tests.csproj -c Release --no-build` (Windows, tout) ; partout : `dotnet run --project tests/Mira.Core.Tests/Mira.Core.Tests.csproj -c Release`.
- App en démo : `dotnet run --project src/Mira.Desktop/Mira.Desktop.csproj -- --demo --data .artifacts/dev-profile`.
- Extension et manifeste : `tools/web/package.sh <x.y.z> [base de téléchargement]` → `dist/web/`.
- Tests Node de Mira web (décisions du lecteur, sans navigateur) : `node --test tools/web/unit/*.test.mjs`.
- Médias de test : `tools/web/media.sh <dossier>`. Jellyfin neuf préparé par l'API : `node tools/web/setup.mjs <serveur> <médias> <user> <mdp> [url du manifeste]`.
- Contrôle Chromium (71 points, 73 avec `MIRA_STOP`/`MIRA_START`, commandes qui arrêtent et relancent Jellyfin) : `PLAYWRIGHT=<.../playwright/index.mjs> node tools/web/check.mjs <url /Mira/> <user> <mdp> "Courte Web" <dossier>`. Le lecteur d'Apple y est simulé.
- Dans le conteneur cloud : Jellyfin par Docker (`dockerd &`, image `jellyfin/jellyfin:12.1.20260915-010956`, `--network host`) ; le SDK .NET d'Ubuntu n'a pas les cibles WPF : SDK de Microsoft depuis les `.deb` de packages.microsoft.com (`debian/12` pour .NET 10 : ni jammy ni noble ne l'ont ; builds.dotnet.microsoft.com est bloqué par le proxy), extraits avec `dpkg-deb -x`, puis `dotnet build -p:EnableWindowsTargeting=true` (compile seulement).
- CI d'une branche : `web.yml` et `ci.yml` se lancent par `workflow_dispatch` (outil GitHub `actions_run_trigger`).
- Audits : la restauration échoue sur une faille NuGet haute ou critique, même transitive (`NuGetAuditMode=all`, `Directory.Build.props`) ; `dotnet list package --vulnerable --include-transitive` (avec `EnableWindowsTargeting=true` dans l'environnement sous Linux) ; mise en forme : `dotnet format whitespace . --folder --verify-no-changes` (CI Windows, sans restauration) ; eslint 9 et shellcheck depuis le scratchpad. Journaux de CI : outil GitHub `get_job_logs` (le proxy refuse les zips d'artefacts et de journaux).
- Contrôle Safari (Mac, `safaridriver -p 4444`, 26 points dont le lecteur d'Apple, 34 avec `MIRA_FORMATS=1` et les médias de `media.sh <dossier> formats`) : `node tools/web/safari.mjs <url /Mira/> <user> <mdp> <dossier>`.
- Servir Mira web depuis le disque sans recompiler : lancer Jellyfin avec `MIRA_WEB_DIR=<chemin de src/Mira.Web>`.
- Publication, sur le PC de l'utilisateur, où est la clé de signature : `git checkout main; git pull --ff-only; .\tools\release.ps1`. Il exige les releases immuables (Settings → Releases → « Enable release immutability »), vérifie gh, la clé (`Mira.Release check-key`), Inno Setup, un arbre propre, `main` identique à GitHub, `ci.yml` réussi sur ce commit et l'absence du tag ; construit les paquets Windows, crée le brouillon (`--draft --target <commit>`), lance `web.yml` et `mac.yml` sur `main` (`-f release=vX.Y.Z -f commit=<sha>`), exige que leurs exécutions soient sur `main` à ce commit, prend leurs fichiers dans leurs artefacts (`Mira-mac-arm64`, `Mira-web-release`), signe (`manifest --others`), vérifie, compare l'empreinte (`digest`) de chacun des 12 fichiers du brouillon, publie, puis vérifie `immutable`. `-DryRun` laisse le brouillon, que le lancement suivant remplace ; `-SkipBuild` reprend les paquets construits depuis le même commit.

## Conventions
- Avertissement = erreur partout (`Directory.Build.props`) ; NU1900-NU1902 (faille basse ou moyenne, source d'avis injoignable) restent des avertissements. Dependabot (`.github/dependabot.yml`) : NuGet et actions, mensuel, groupé, 7 jours de recul, pas de majeure NuGet ni de `Jellyfin.Controller`.
- `.editorconfig` décrit le style réel (plusieurs instructions par ligne, initialiseurs compacts, `case` en bloc non indenté). Le formateur met quand même un bras de `switch` et un membre de `with { }` multiligne par ligne : pas d'option pour ça. Les formateurs des SDK 8 et 10 ne s'accordent pas sur le corps d'un `else foreach` sans accolades : des accolades.
- Interface et docs en français, en tutoyant ; messages de commit en anglais.
- Fins de ligne : CRLF pour `.cs`, `.xaml`, `.axaml` ; LF pour `.sh`, `.md`, `.yml`, `.json`, `.js`, `.mjs`, `.css`, `.html`, `.webmanifest` (`.gitattributes`).
- Chaque version a son entrée dans `WhatsNew.json` (résumé ≤ 100 caractères, 2 à 5 points, icônes dessinées par Mira) : le test « Nouveautés : bienvenue… » le vérifie.
- `CHANGELOG.md` : section « Non publié » en haut, datée à la publication.
- Version : `<Version>` dans les csproj Desktop, Mac et Jellyfin ; ne la change qu'à la préparation d'une release demandée.
- Les PR se fusionnent en rebase (depuis la session, à la demande de l'utilisateur) ; la publication se fait depuis son PC.
- Windows : couleurs nommées dans `Themes/Cinema.xaml` (`Bg`, `Text`, `TextSecondary`, `Field`, `Raised`, `Accent`, gelées ; `Muted` et `Faint` changent en contraste élevé), à utiliser plutôt qu'une valeur écrite ; le contrôle de contraste lit `Text` et `TextSecondary`.
- Mira web : design sombre (tokens dans `:root` de `app.css`), police Nunito Sans auto-hébergée, icônes Phosphor (`js/icons.js`). Taille de texte en `calc(Npx * var(--text))` (réglage « Taille du texte »), sauf libellés des onglets et du lecteur.

## Décisions (et pourquoi)
- 2026-10-08 — Mac en Avalonia avec libmpv embarquée — partage `Mira.Core` et le même lecteur que Windows.
- 2026-10-09 — iPhone par une app web servie par une extension Jellyfin — ni App Store, ni compte Apple, ni AltStore à rafraîchir, gratuit.
- 2026-10-11 — Dépôt de l'extension = `releases/download/vX.Y.Z/jellyfin-manifest.json` de la version de Mira pour Windows, vérifiée par sa signature ; releases en brouillon, signées en dernier, publiées d'un coup, immuables — Jellyfin ne vérifie qu'un MD5 fourni par la même release (SEC-02).
- 2026-10-09 — Une seule `<video>` partagée, débloquée au premier toucher — iOS n'autorise le son qu'après un geste ; l'épisode suivant démarre ainsi seul.
- 2026-10-09 — Profil d'appareil : H.264 avant HEVC en HLS — conversion le plus souvent sans réencodage.
- 2026-10-09 — iPhone et iPad : lecture uniquement dans le lecteur plein écran d'Apple (pas de `playsinline`) — demandé par l'utilisateur (commandes d'Apple). Audio et sous-titres choisis sur la fiche : le menu d'Apple ne change pas l'audio d'une conversion.
- 2026-10-10 — Dynamic Island : défaut d'iOS pour les apps de l'écran d'accueil (WebKit la masque par identifiants d'app qui ne correspondent pas ; en plein écran, iOS 27 la demande même), rien dans la page n'y change rien ; seul levier : session audio `ambient`, la seule mêlable, que le mode silencieux coupe (aucun type ne donne les deux, sources de WebKit) : option « Masquer la Dynamic Island », iPhone seulement, qui le dit.
- 2026-10-10 — Flux refusé par le lecteur (Jellyfin répond) : redemandé la vidéo convertie, puis tout converti (`lastResortProfile`, H.264 SDR ≤ 1080p, AAC stéréo), de là où il en était — une qualité plus basse ne change rien (Jellyfin copie la vidéo sous le plafond, l'audio toujours) ; profil aligné sur jellyfin-web pour Safari (`VideoRangeType`, `IsInterlaced`, niveau HEVC).
- 2026-10-10 — Onglets : pas de View Transition (les barres givrées perdent leur flou) ; l'écran d'un onglet attend d'être prêt (`ready`, 250 ms au plus) puis l'écran quitté se fond dans un calque fixe (`dissolve`) ; cartes mises à jour sur place (`reconcile`/`cardSig`).
- 2026-10-10 — Sous-titres d'une conversion dans le flux HLS (`appleStream` réécrit l'adresse en `SubtitleMethod=Hls`), liste principale servie par `/Mira/hls/…` (extension) : AirPlay, un seul jeu de pistes, et Jellyfin date ses WebVTT HLS pour des segments TS (`MPEGTS:900000`, 10 s de retard en fMP4).
- 2026-10-10 — ASS/SSA en texte (profils `External`, lus en `.vtt`), partout : sinon Jellyfin les incruste en réencodant toute la vidéo ; la mise en forme est perdue.
- 2026-10-10 — Navigation d'app iOS : View Transitions (glissement à droite), onglets qui reviennent au bas de l'historique ; le glissement depuis le bord est celui d'iOS (apps de l'écran d'accueil, depuis 12.2), Mira ne redessine pas ce retour.
- 2026-10-09 — Épisode suivant dans le même lecteur (`history.replaceState`) — retirer la `<video>` du document quitte le plein écran.
- 2026-10-09 — `/Mira/` gardée un mois par le téléphone, révision vérifiée à chaque démarrage — l'app s'ouvre PC éteint et attend le serveur ; pas de service worker en HTTP.
- 2026-10-10 — Pare-feu lu et ouvert par le guide, pour le Wi-Fi de la maison et pour Tailscale, avec ou sans service : un Jellyfin sans service n'a que les règles de l'invite de Windows (bloqué sur les profils non cochés, ou partout si elle n'a pas été validée), Tailscale déclare son réseau privé, la box est souvent publique. Les blocages qui s'appliquent perdent ces profils (pas supprimés), puis règle « Mira - Jellyfin ».
- 2026-10-10 — Téléphone : une seule carte du guide, étapes cochées, « Tout préparer » (une autorisation de Windows), QR code à l'adresse Tailscale quand elle est prête — demandé par l'utilisateur (« beaucoup plus simple pour les nouveaux utilisateurs ») ; l'adresse Tailscale marche aussi à la maison, Tailscale activé.
- 2026-10-09 — Démarrage avec Windows : `sc config start= auto` (différé gardé, WIN-05), `sc failure` (trois relances puis rien) + `failureflag 1` (pas `AppExit Restart` : un arrêt voulu reste un arrêt), règles de pare-feu `localsubnet` et `100.64.0.0/10` pour `jellyfin.exe` — l'installateur n'ajoute aucune règle pour son service.

## Fragile / ne pas toucher sans raison
- Sur iOS en HTTP local : pas de service worker, pas de `crypto.randomUUID`, de presse-papiers ni de Wake Lock.
- L'extension doit hériter de `BasePlugin<BasePluginConfiguration>` : sinon sa version est nulle et Jellyfin la marque « en défaut ».
- `WebFiles.Types` doit connaître chaque extension servie : `.mjs` manquant = page du QR code cassée ; un type inconnu va dans `Unserved` (journal de Jellyfin) et fait échouer le test « chaque fichier de l'app est servi ».
- Commandes du lecteur masquées (`.player.idle`) : `pointer-events: none` ; un test doit les réafficher avant de cliquer.
- Le cadre de la `<video>` épouse l'image (`.player.fitted`) : Safari place les sous-titres en bas du cadre.
- Lecteur d'Apple : les `<track>` doivent être ajoutées **avant** `src` (WebKit les passe à AVFoundation au chargement). Les changements de pistes ne sont suivis qu'en plein écran et 1,5 s après le chargement (sinon le navigateur en fait de faux choix). Sur Mac, le plein écran demande un toucher (plein écran d'élément) ; sur iPhone, non après le premier geste.
- Pendant son démarrage, Jellyfin 12 répond à `System/Info/Public` (en camelCase) et 503 au reste : seul `System/Ping` prouve qu'il est prêt.
- `EnableSubtitlesInManifest` n'est lu par Jellyfin que pour `live.m3u8` : pour un film, c'est `SubtitleMethod=Hls` dans l'adresse (sans `SubtitleStreamIndex`, tous les sous-titres sont `DEFAULT=NO`). Jellyfin écrit `SubtitleMethod=Encode` même pour -1 (aucun) : ce n'est pas une incrustation.
- Jellyfin ne convertit jamais ASS/SSA par le profil (`SupportsSubtitleConversionTo`) : sans profil `External` pour eux, il les incruste.
- WebKit : régler une piste sur le mode qu'elle a déjà ne compte pas ; une piste jamais réglée par la page est choisie par WebKit (langue, défaut, forcée). Un choix dans le menu d'Apple change aussi les réglages de sous-titres de l'iPhone.
- WebKit garde `:active` pendant un défilement commencé sur l'élément : appuis par `press.js` (`.pressed`), `:active` pour la souris seulement.
- Erreur de flux : n'attendre le serveur que si `ping()` échoue (sinon boucle de réouvertures sur une erreur 500) ; `<track kind="forced">` n'existe que dans Safari (ailleurs : metadata, jamais affiché).
- Lecteur d'Apple : sur un changement de source, `webkitpresentationmodechanged` peut arriver après que Mira a redemandé le plein écran ; la fermeture pendant l'épisode suivant se lit sur `presentation()` (`switchFrom`).
- ffmpeg : `-shortest` compte aussi les sous-titres (le film de test ASS faisait 3 s) : durée par `-t`.
- Jellyfin : segments HLS TS à 10 s, fMP4 à 0 ; ses WebVTT HLS ont `MPEGTS:900000` en dur. hls.js s'en moque, le lecteur d'Apple non.
- View Transitions : le changement d'écran se fait dans un rappel différé ; `enter()` et tout ce qui touche l'écran affiché vont dans `swap`.
- Vérifier la syntaxe des modules avec `node --experimental-default-type=module --check` (sans l'option, une redéclaration passe).
- `stream.js`, `timeline.js`, `presentation.js`, `tracks.js` et `dom.js` sont importés par Node (`tools/web/unit`) : rien du navigateur au chargement du module. Tests hors de `src/Mira.Web` (tout y est intégré à la DLL et servi).
- Avec `MIRA_WEB_DIR`, la page n'est pas gardée (no-cache) : tester « serveur éteint » avec l'extension compilée.
- Fichiers `.srt` de test : pas d'accents (Jellyfin devine mal l'encodage d'un fichier d'une ligne).
- Safari peut attendre un geste avant de lire : les tests partent du bouton « Lecture » de la fiche, pas d'un changement d'adresse.
- Chromium de Playwright ne lit ni H.264 ni AAC : les tests Chromium utilisent des WebM.
- Jellyfin ne garde une reprise qu'après 5 min par défaut : `setup.mjs` met `MinResumeDurationSeconds` à 1 pour les tests.
- Scripts lancés sur Mac : pas de `md5sum` ni de `base64 -w`.
- Jellyfin 12.1 n'écrit `allowVideoStreamCopy=false` dans l'adresse que pour HLS ; il met `VideoCodec=` même quand il copie : `copiesVideo` lit `TranscodeReasons`. Il ne lit plus `BreakOnNonKeyFrames` ni `MinSegments` (VOD), ni les étiquettes de codec (`codec_tag_string?` en 12.0/12.1).
- Jellyfin 12.1 ne sait pas reconvertir en VP9 un VP9 de niveau inconnu (`level -99`, ffmpeg 222) : le test de la cascade dans Chromium part d'un film H.264.
- Une image `loading=lazy` dans un écran pas encore affiché ne se charge jamais : `ready` ne décode que les `img[loading="eager"]`.
- Une carte gardée par `reconcile` reçoit le nouvel objet (`card.item`) : ses menus lisent `card.item`.
- Pare-feu de Windows : une règle de blocage l'emporte sur toute autorisation ; l'invite « Autoriser l'accès » crée des blocages pour les profils non cochés. Lu et modifié par `HNetCfg.FwPolicy2` en `dynamic` (IDispatch, par nom : une interface `ComImport` mal ordonnée appellerait une autre méthode, dans une copie administrateur) ; propriétés indexées : `policy.FirewallEnabled[profil]`.
- « Tout préparer » : une étape `ToDo` doit être faisable par Mira, sinon l'autorisation de Windows revient à chaque clic ; ce que Mira ne change pas (tout bloquer, règle sans programme, programme introuvable) est `Yours`. Jellyfin qui ne répond pas (`System/Ping`) : rien n'est conclu, la carte relit quand il répond.
- Profil de chaque carte réseau : `MSFT_NetConnectionProfile` (WMI, `WbemScripting.SWbemLocator` en `dynamic`, sans droits). Le nom de carte (`InterfaceAlias`) est le `NetworkInterface.Name` de .NET.
- Les contrôles du Mac (VM) refusent le HEVC 10 bits HDR10 copié (« Media failed to decode ») : il passe par la vidéo convertie.
- `LibraryStore` : `CreateSchema`, `PRAGMA quick_check(1)` et `Prune` dans le même `try`, base mise de côté sur les codes 11, 26 et les codes étendus 266 (`IOERR_READ`, Windows) et 8458 (`IOERR_CORRUPTFS`, EIO sous macOS et Linux) ; disque plein, verrou ou lecture seule remontent aux appelants, qui le disent. `quick_check` décrit en texte (« ok » sinon) une page abîmée ou illisible, sans lever, sauf la page 1, que toute requête lit. Secteur illisible simulable sous Linux : LD_PRELOAD qui renvoie EIO à `pread64`. Pas de repli `:memory:` (une connexion par opération). Le cache est un bonus : les lectures et écritures des actualisations passent par `TryCache`.
- Gestionnaire global WPF (`App.xaml.cs`) : fenêtre ouverte, `Handled = true` et message ; avant `Show()` ou pendant la fermeture (`IsClosing`), `Shutdown(1)`, sinon un processus sans fenêtre garde le mutex (« déjà ouvert » à chaque relance). `Window_Closing` et le `OnClosing` du Mac font chaque étape dans `Attempt` (type et méthode dans `errors.log`, `ErrorLog`) et ferment dans `finally` : une nouvelle étape de fermeture y va aussi. `--windows-check` écrit `failure.txt` (`CheckFailed`) même si la fenêtre ne se crée pas. Mac : `Dispatcher.UIThread.UnhandledException`, même règle, `--self-check` laissé planter.
- Délai de `HttpClient` (12 s) = `TaskCanceledException` (une `TimeoutException` dedans), jeton de l'appelant intact : n'ignorer une annulation que `when (ct.IsCancellationRequested)`, avec le jeton de l'opération pris au départ (`_connectionLifetime` change avec le compte), sinon un serveur muet ne donne aucun avis ; une actualisation en arrière-plan (`quiet`) l'ignore aussi tant que la page montre quelque chose (`!_catalogLoading`). `IsExpected` (Windows) et `Errors.Expected` (Mac) passent par `ExpectedErrors.Are` (Core) : une saisie refusée lève `UserInputException`, la seule `ArgumentException` attendue ; toute autre est un défaut, qui va au gestionnaire global (`errors.log`).
- Réglages illisibles (`SettingsUnreadable`) : copie `settings.json.bad-<date>` au chargement ou, à défaut, avant le premier enregistrement, Windows et Mac. Windows : `TrySaveSettings` ne lève jamais (journal, réglages gardés en mémoire, la fermeture réessaie) ; tout chemin qui masque `SettingsOverlay` appelle `AutoSaveSettings()` d'abord ; un avis du démarrage s'ajoute par `AddNotice` sans remplacer l'avis affiché. Sous Linux et macOS, `FileShare.None` n'est qu'un verrou consultatif : un fichier « retenu » ne se teste que sous Windows.
- `Mira.Jellyfin` fixe son TFM à `net8.0` (Jellyfin 10.9 et 10.10 tournent en .NET 8) ; les apps prennent celui de `Directory.Build.props`. `licenses/DOTNET-THIRD-PARTY-NOTICES.txt` = `THIRD-PARTY-NOTICES.TXT` du paquet `microsoft.netcore.app.runtime.win-x64` de la version embarquée (fins de ligne LF).
- Stockage du site bloqué (« Bloquer tous les cookies ») : lire `localStorage`/`sessionStorage` lève. `sessionStorage` passe par `temp` (`session.js`, repli en mémoire) ; un rechargement gardé par une note (`mira.update`, `mira.reloaded`) ne se fait que si `temp.set` a réussi, sinon il boucle.
- Pas de `content-visibility` sur les cartes : son confinement de peinture rogne le soulèvement (`.holding`) et l'anneau de focus. Grille : pages de 60 au défilement, actualisée par sa première page (`GRID_FIELDS`, sans résumé).
- Débit « Automatique » : mesure gardée une heure (`player.js`) ; Tailscale n'est pas « la maison » (son adresse sert aussi en 4G), contrairement à `isLocalHost` qui sert à l'avertissement HTTP.
- Mira web n'envoie le jeton qu'après `trustServer()` (dans `request()`) : un `fetch` direct qui porte le jeton l'appelle d'abord (comme `bitrateTest`) ; les appels publics passent `token: null`. Jellyfin qui démarre (`System/Info/Public` en camelCase, puis 503) n'est pas un « serveur étranger ».
- Politique de sécurité de Mira web sans `'unsafe-inline'` : jamais d'attribut `style=` (HTML, `innerHTML`, `setAttribute('style')`, `cssText`), seulement `h(…, { style: {…} })` ou `el.style.x` ; le `<style>` d'`index.html` est permis par son empreinte (`ContentPolicy`). Une clé de compte dans `localStorage` commence par `mira.home.` ou `mira.library.`, ou va dans `ACCOUNT_SETTINGS` (`session.js`), pour être effacée à la déconnexion.
- Pare-feu : la règle de Mira est jugée sur son contenu (`JellyfinFirewall.MiraRule`, COM par nom), profils `JellyfinStartup.RuleProfiles` (domaine, privé) pour l'écrire et la juger ; jugement des deux origines dans Core (`JellyfinFirewall.Phones`, testable sous Linux). Un réseau public n'est passé en privé que par « Passer en privé » (`ApplyAsync(port, privateNetwork: true)`, WMI `MSFT_NetConnectionProfile`, `Put_(1)` dans le script, jamais un domaine ; refus relu par Mira = `KeptPublic`), jamais par « Tout préparer » seul (SEC-03).
- Connexion (Windows, Mac) : `ServerAddress` ne refuse un HTTP après un certificat refusé que pour un nom d'Internet (`InternetName`), jugé sur l'adresse finale ; `ExposesPasswordAsync` compte toujours un nom d'Internet comme Internet (le DNS d'un point d'accès peut mentir). Sous Linux et macOS, du TLS envoyé à un port HTTP lève une `AuthenticationException` (compté comme certificat refusé). Dans le conteneur, .NET ignore les CIDR de `NO_PROXY`.
- Déconnexion : session locale effacée d'abord, puis `Sessions/Logout` (3 s au plus) ; écran de connexion inactif pendant ce temps (`_signingOut`). Noms des caches d'un compte dans `AccountData` seulement ; `LibraryStore.Delete` vide le pool SQLite avant de supprimer.
- Mac, trousseau (`Keychain.cs`, élément générique « Mira », compte = dossier du profil) : repli silencieux sur `session.json` 0600 ; appels jamais sur le fil de l'interface ; marqueurs `keychain-forget` (jeton à retirer), `keychain-version` (stocké de nouveau une fois par version), `keychain-refused` (pas redemandé avant une connexion ou une mise à jour). Signée ad hoc, chaque version est une autre app : question au premier lancement (« Toujours autoriser »). Le self-check garde un profil sans trousseau. `Mira.Tests` compile `Profile.cs` : il ne dépend que de Mira.Core.
- TorLink : lock dans `src/Mira.Core/TorLink/Lock` (intégré ; le changer : `docs/ARCHITECTURE.md`, « Changer le lock ») ; `version.txt` = version + SHA-256 du lock. Un TorLink `Detected` (raccourci, npm global) n'est jamais lancé sans « Utiliser ce TorLink ». Node.js, TorLink, libmpv préparés dans `node-next`, `torlink-next`, `mpv-next` ; Node.js et TorLink mis en place par deux renommages (`PreparedFolder`, `Restore` avant `Locate`), libmpv dans `App` après le mutex d'instance ; charge utile vidée sur le disque avant le tampon de version.
- Mise à jour en dossier : `IN-PROGRESS.json` dans `data/updates/rollback-…` avant le premier renommage ; ancien fichier lié (lien physique) dans le rollback, copié en entier (`CopyWhole`) si le profil est sur un autre disque, mis de côté (`.mira-old`) s'il ne se remplace pas sur place. Un journal qui reste après l'échange garde le rollback entier (`Finish`) : le démarrage suivant revient à la version précédente. `RecoverAtStartup` ne restaure rien sous un Mira du même profil ouvert, puis relance avec `--after`. Un fichier lié mais pas remplacé ne doit pas être « remis » (CreateHardLink réussit sur un fichier ouvert sans partage).
- Un test sans WPF va dans `tests/Mira.Core.Tests` (un fichier de Desktop sans WPF y est lié par son csproj : `UpdateApplier.cs`, `Updater.cs`…) ; un test qui ne passe que sous Windows (chemins, liens physiques, DPAPI) va dans `tests/Mira.Tests/Program.cs`. Code commun Windows/Mac dans Core : `IconPaths`, `MpvLists`, `PlaybackMarkers.Offer`.
- `mira-update.json` : `files` = installer/portable/zip seulement (0.5.2 à 0.7.4 refusent un type inconnu) ; Mac et extension dans `others`, lus avec indulgence par `Parse` (strict dans `MiraWebRelease` et `Mira.Release`). Clé introuvable : `import-backup`, jamais `keygen`.
- Mira web : Mira pour Windows enregistre `releases/download/vX.Y.Z/jellyfin-manifest.json` après `MiraWebRelease.VerifyAsync` (release immuable, signature, extension) et retire les autres dépôts de Mira ; au démarrage, `KeepWebAppCurrentAsync` n'avance que le dépôt, jamais en arrière, sans `Packages/Installed` ; un dépôt ajouté à la main (`releases/latest`) n'est pas vérifié. `mac.yml` et `web.yml` ne partent plus sur `release: published` : ils n'envoient qu'à un brouillon visant leur `commit`, sans `--clobber`. `GET repos/…/immutable-releases` répond 200 `{"enabled":false}` quand c'est désactivé : lire `enabled`.
- Avalonia (Mac) embarque une télémétrie de construction (`Avalonia.BuildServices`) : coupée par `<UsedAvaloniaProducts></UsedAvaloniaProducts>` dans `Mira.Mac.csproj`, son seul déclencheur ; à revérifier à chaque version d'Avalonia (`dotnet build -v:d` : « Target "AvaloniaStats" skipped »).
- Mac : les bibliothèques de Homebrew demandent le macOS du runner qui les construit (`macos-15`) ; `MINIMUM` de `tools/mac/package.sh` (15.0) est vérifié sur chaque bibliothèque embarquée : changer de runner, c'est changer ce minimum, le README, `docs/INSTALLATION-MAC.md` et le texte de release (`WhatsNew.cs`, « Sur Mac »).
- Mac : dylibbundler change chaque rpath de libmpv en `@loader_path/` ; deux fois le même, et dyld refuse la bibliothèque sur `macos-15` (« duplicate LC_RPATH », pas sur `macos-14`) : `package.sh` n'en garde qu'un, puis charge libmpv (`python3` + `ctypes`) pour arrêter la construction sur la raison de dyld.
- Élévation (SEC-04) : jamais `Mira.exe` (son dossier est modifiable sans droits) ; Windows PowerShell 5.1 avec `-EncodedCommand` : pas de `??` ni de ternaire, aucune cmdlet ni module (`$PSModuleAutoLoadingPreference = 'None'`, un module de Documents tournerait en administrateur), textes du plan en base64 seulement, ligne de commande ≤ 30 000 caractères (`MaximumArguments`). Les tests Windows passent par le même script sans élévation ; sous Linux, `pwsh` le fait tourner avec de faux `sc.exe`/`netsh.exe` dans le dossier courant (`[Environment]::SystemDirectory` y est vide).
- `sc failure … actions= restart/…/restart/60000//0` : Windows répète la dernière action à chaque échec suivant ; la quatrième, vide, arrête les relances (vérifié par le test CI sur `FailureActions`).
- Network Service ne reçoit la lecture que sur `Films`, `Séries`, `Animes` (pas la racine : le privilège de traverser suffit) ; les copies 0.7.4 et avant l'ont sur toute la racine, retrait décrit dans `docs/INSTALLATION.md`.
- Mac : `package.sh` retrouve la formule de chaque bibliothèque embarquée par le chemin réel dans `Cellar/<formule>/<version>` et échoue si l'une n'en a pas ; `HOMEBREW-LIBRARIES.txt` et les textes GPL/LGPL de `licenses/` vont dans `Contents/Resources` avant la signature.
- Arrêt de Windows ou Restart Manager (`CloseApplications` de l'installateur) : WPF lève `SessionEnding` puis ferme la fenêtre sans attendre (Closing non annulable) et le processus peut finir dès la réponse : ce qui doit survivre est dans `KeepForNextStart` (synchrone, borné, avant le premier `await` de `Window_Closing`) et dans `SessionEnding` (« stop » mis en file, 1,5 s au plus).
- `InstanceActivation` : canal hors du fil de l'interface (`ConfigureAwait(false)`), créé juste après le mutex ; sinon un Mira qui démarre ne répond pas à temps (faux « déjà ouvert »). Réponses `shown`/`starting`/`closing` ; « closing » : la relance attend le mutex puis refait les contrôles (verrou de mise à jour compris).
- Placement de la fenêtre (Windows) : `ScreenFit.Place` en pixels physiques, appliqué à `SourceInitialized` (déplacement sans taille, puis taille) ; `WindowState = Maximized` après ce déplacement, jamais dans le constructeur (créée agrandie là où Windows la met).
- Noms pour le Narrateur (Windows) : WPF ne nomme un bouton d’après son contenu que si c’est un texte ; le style `Button` de `Cinema.xaml` lie `AutomationProperties.Name` au texte du contenu (`Accessible.ContentName`), une icône seule doit avoir son nom. Chaque capture des contrôles (`CaptureAsync`) échoue sur un contrôle visible sans nom (`AssertNamed`). Snap Layouts : `SnapHook` répond `HTMAXBUTTON` et doit être ajouté après le crochet de `WindowChrome` (le dernier ajouté passe en premier) ; WPF ne voit plus la souris sur ce bouton (survol et clic par messages non-client). `System.Windows.Readability` existe : la classe de Core s’appelle `Legibility`.
- Veille : `_fileOpen` vaut de `Load` jusqu'à END_FILE (chargé ou non) ; rouvrir le flux saute la fin de l'ancien (`_skipEnds`). Une fin pendant la veille ou avant la réponse de Jellyfin n'est jamais une fin de titre ; un flux rouvert qui échoue n'est jamais « vu ».
- Images (Windows) : décodées à la taille affichée × échelle de l'écran le plus net (`Artwork.Pixels`, par paliers : la largeur est dans la clé et le fichier) ; une affiche de la grille ne demande son image qu'à l'approche de l'écran (`LoadVisibleArtwork`) : une capture attend `ImageReady` des cartes, pas `ImageCache.GetAsync` (autre largeur, autre clé). `LibraryStore.Save` saute une page identique (empreinte en mémoire, réécrite une fois par jour) : toute écriture de `cache` passe par `Save`.
- Carrousel (Windows) : `DispatcherTimer` à 30 Hz arrêté en pause (`HeroPaused`) : une nouvelle cause de pause appelle `UpdateHeroClock` quand elle change. `SyncService` dort sans rien à envoyer : Jellyfin revenu → `Wake()`. « Hors connexion » vient de `_offlineSince` (`SyncStatus`), jamais écrit à la main dans `SyncLabel`.
