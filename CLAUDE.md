# Mira

## Objectif
Client Jellyfin « cinéma » : une app Windows native avec mpv intégré, sa version Mac et une app iPhone native (AltStore Classic), plus une extension
Jellyfin (party, invités, relais, sous-titres). Pas d'Android pour l'instant ; Mira web retirée (2026-11-05). Pour un particulier qui regarde sa bibliothèque chez lui et ailleurs.

## Stack
- .NET 10 (`global.json` : SDK 10.0.100, roll forward dans 10.0), C#. L'extension Jellyfin reste en `net8.0` (Jellyfin 10.9 et 10.10 tournent en .NET 8).
- Windows : WPF (`src/Mira.Desktop`), lecteur libmpv. Mac : Avalonia (`src/Mira.Mac`), libmpv embarquée, `.dmg`, macOS 15 ou plus (après la 0.7.4).
- iPhone : SwiftUI (`src/Mira.iOS`), iOS 26, Swift 6 strict, projet XcodeGen (`project.yml` ; `.xcodeproj` et `Info.plist` générés, ignorés par git), catalogues `.xcstrings` (anglais source, français), sans autre dépendance que le nœud de Tailscale intégré (`src/Mira.Tailscale/ios` en `MiraTailscale.xcframework` par `tools/ios/tailscale.sh`, ignorée par git) ; rien de partagé avec Core (règles portées avec leurs tests).
- Code commun : `src/Mira.Core`. Pages de l'extension (`src/Mira.Jellyfin/Pages` : `/Mira` = adieu à Mira web et liens vers les apps, page de party) : HTML, CSS, JS sans build, sans dépendance.
- Extension : `src/Mira.Jellyfin`, compilée contre Jellyfin.Controller 10.9.11, chargée par Jellyfin 12.1. Serveur : Jellyfin 10.9 ou plus. `net8.0` n'est qu'une cible de compilation : l'extension tourne dans le .NET de Jellyfin (12.x = .NET 10, 10.11 = .NET 9, 10.9 et 10.10 = .NET 8), la fin de .NET 8 (2026-11-10) ne la concerne pas.

## Commandes (celles d’un sujet précis : `docs/COMMANDES.md`)
- Build : `dotnet restore Mira.sln --configfile NuGet.Config` puis `dotnet build Mira.sln -c Release --no-restore`. Mac et extension hors de `Mira.sln` : `dotnet build src/Mira.Mac/Mira.Mac.csproj -c Release` (compile aussi sous Linux), `dotnet build src/Mira.Jellyfin/Mira.Jellyfin.csproj -c Release` (essai sur le Jellyfin du conteneur : copier la DLL dans `plugins/Mira_<version>/` puis `docker restart`). Démo : `dotnet run --project src/Mira.Desktop/Mira.Desktop.csproj -- --demo --data .artifacts/dev-profile`. Nœud de « Tailscale intégré » : `node tools/tailscale/build.mjs windows/amd64 .artifacts/tailscale/windows-amd64` (Go 1.21 ou plus, qui télécharge le Go exact de `go.mod` ; Go absent du PATH : le plus récent des `GOROOT_1_*` d'un runner) avant la compilation : `Mira.Desktop.csproj` le met à côté de `Mira.exe`, ou dans le portable (`MIRA_TAILSCALE_EMBEDDED`), avec son SHA-256 ; sans lui, Mira compile sans la fonction.
- Tests (2026-11-09 : 287 réussis sous Linux dans `tests/Mira.Core.Tests`, exécution locale, 240 avec le vrai nœud de Tailscale intégré : `MIRA_TAILNET_HELPER=<mira-tailscale> MIRA_TAILNET_TESTNET=<mira-testnet>`, compilés dans `src/Mira.Tailscale` par `go build -tags "$(cat build-tags.txt)" -ldflags "-X main.version=test" ./cmd/mira-tailscale` et `./cmd/mira-testnet` ; le bilan final de chaque exécution donne le compte, ne l'additionne pas) : `dotnet run --project tests/Mira.Tests/Mira.Tests.csproj -c Release --no-build` (Windows) ; partout `dotnet run --project tests/Mira.Core.Tests/Mira.Core.Tests.csproj -c Release`.
- Extension : `tools/web/package.sh <x.y.z> [base]` → `dist/web/` (zip et manifeste du dépôt) ; médias `tools/web/media.sh <dossier>` ; Jellyfin neuf `node tools/web/setup.mjs <serveur> <médias> <user> <mdp> [manifeste]` ; contrôle par son API (party, invités, relais, sous-titres, pages) `node tools/extension/check.mjs <serveur> <user> <mdp> <dossier>`, lancé par `web.yml` sur Jellyfin 10.9.11, 10.10.7, 12.1, 12.4 et `latest` (`latest` ne fait échouer que l'exécution du lundi). `web.yml` garde son nom et son artefact `Mira-web-release` (lus par `release.ps1` et `release-check.ps1`).
- Conteneur cloud : Jellyfin par Docker (`dockerd &`, `jellyfin/jellyfin:12.1.20260915-010956`, `--network host`) ; SDK .NET de Microsoft depuis les `.deb` de packages.microsoft.com (`debian/12` : ni jammy ni noble n'ont .NET 10 ; builds.dotnet.microsoft.com bloqué), `dpkg-deb -x`, puis `-p:EnableWindowsTargeting=true` (compile seulement).
- CI d'une branche : `web.yml` et `ci.yml` par `workflow_dispatch` (`actions_run_trigger`) ; journaux : `get_job_logs` (le proxy refuse les zips). Un push sur une PR qui ne lance aucune CI = PR en conflit avec `main` (GitHub ne lance pas `pull_request` tant qu'elle l'est) : rebase sur `main` puis push (`CHANGELOG.md` en `merge=union` : les lignes des deux côtés gardées, relire si une même ligne a changé des deux côtés). `ci.yml`, `web.yml`, `ios.yml` et `mac.yml` : un nouveau push sur une PR annule son run en cours.
- `mac.yml` sur une PR (2026-11-04, build trop long pour ogsas) : seulement si elle touche `src/Mira.Mac`, le nœud Tailscale, `tools/mac`, `tools/tailscale` ou le workflow (Core seul : Mira.Mac compilé sous Linux par le job `portable` de `ci.yml`) ; un nouveau push annule le run précédent de la PR ; `Assets.car` en cache (job `icon`, clé = empreinte de `Mira.icon` et `icon-car.sh` : icon-car et icon-check sautés sur PR) ; étapes Tailscale intégré seulement si un fichier changé contient `tail`, `keychain`, `profile`, `tools/mac/` ou `mac.yml`. `main` et les releases : tout, comme avant.
- Audits : restauration en échec sur faille NuGet haute ou critique, même transitive (`NuGetAuditMode=all`) ; `dotnet list package --vulnerable --include-transitive` (`EnableWindowsTargeting=true` sous Linux) ; `dotnet format whitespace . --folder --verify-no-changes` (CI) ; eslint 9 et shellcheck depuis le scratchpad.
- Publication : ogsas, depuis son PC : `git checkout main; git pull --ff-only; .\tools\release.ps1 -Unsigned`, après une PR de préparation (version des csproj, `WhatsNew.json`, `CHANGELOG.md` daté, bannière `docs/releases/x.y.z.jpg`) ; tout le détail : `docs/COMMANDES.md`.

## Conventions
- Avertissement = erreur partout (`Directory.Build.props`) ; NU1900-NU1902 (faille basse ou moyenne, source d'avis injoignable) restent des avertissements. Dependabot (`.github/dependabot.yml`) : NuGet et actions, mensuel, groupé, 7 jours de recul, pas de majeure NuGet ni de `Jellyfin.Controller`.
- `.editorconfig` décrit le style réel (plusieurs instructions par ligne, initialiseurs compacts, `case` en bloc non indenté). Le formateur met quand même un bras de `switch` et un membre de `with { }` multiligne par ligne : pas d'option pour ça. Les formateurs des SDK 8 et 10 ne s'accordent pas sur le corps d'un `else foreach` sans accolades : des accolades.
- ANGLAIS D'ABORD (ogsas, 2026-10-30) : `README.md` à la racine en anglais (le français : `docs/README.fr.md`), notes de release et textes publics en anglais, app en anglais par défaut ; les guides de `docs/` restent en français pour l'instant. Docs en français, en tutoyant ; messages de commit en anglais. Interface en anglais et en français (anglais par défaut) : chaque texte écrit dans les deux langues là où il sert, `L("français", "English")` de `Lang` (Core, `using static Mira.Core.Lang`), pluriels par `Count`/`Plural`, heures et dates par `Time`/`Day`/`Date`, nombres par `Lang.Culture` ; langue = réglages (`PlayerSettings.Language`), sinon installation, sinon système ; appliquée au démarrage. Termes communs aux apps et à Mira web : `/mnt/project-files/anglais/glossaire.md`. Les tests partent en français (`TestRun`).
- Fins de ligne : CRLF pour `.cs`, `.xaml`, `.axaml` ; LF pour `.sh`, `.md`, `.yml`, `.json`, `.js`, `.mjs`, `.css`, `.html`, `.webmanifest` (`.gitattributes`).
- Chaque version a son entrée dans `WhatsNew.json` (`date` = celle de `CHANGELOG.md`, résumé ≤ 100 caractères, 2 à 5 points, icônes dessinées par Mira, `changes` = 2 à 12 lignes « Catégorie : texte » (catégorie ≤ 24, texte ≤ 140, listées par « Nouveautés », les notes de release, Discord, winget et AltStore ; sans elles, les points), anglais dans `"en"` de l’entrée, de chaque point et de chaque ligne ; la page de release GitHub est faite de l’anglais seulement ; écris l’anglais d’abord, c’est lui que le public lit) : le test « Nouveautés : bienvenue… » le vérifie. `"web": true` sur un point que Mira web montre aussi (« Nouveau dans Mira », une fois sur le téléphone, texte valable pour lui) ; sans point marqué, le téléphone ne montre rien de cette version.
- Avis (`SetNotice`, `Notice`, `notice` de l’iPhone) : jamais pour ce que l’écran montre déjà (bouton qui change, ligne qui part : « marqué comme vu » retiré le 2026-11-05, demandé par ogsas) ; seulement une erreur, ce qui ne se voit pas ailleurs (presse-papiers, arrière-plan, autre appareil, ce que Jellyfin fera plus tard) ou un avis à bouton (« Annuler », « Redémarrer »).
- `CHANGELOG.md` : section « Non publié » en haut, datée à la publication.
- Version : `<Version>` dans les csproj Desktop, Mac et Jellyfin ; ne la change qu'à la préparation d'une release demandée.
- Les PR se fusionnent en rebase (depuis la session, à la demande de l'utilisateur) ; la publication se fait depuis son PC.
- Windows : palette unique dans `Themes/Cinema.xaml` (fonds `Bg` à `LineStrong`, encres `Text` à `Dim`, `OnAccent`, états `Success`/`Warning`/`Danger`, calques `Hairline`, `Menu`, `Toast`, `Sheet`…), noms de Mira web, gris neutres (R = G = B, sans la teinte bleue de Mira web : choix d’ogsas le 2026-10-31, banding et teinte sur un OLED), fond `Bg` noir pur #000 partout, Windows, Mac (`App.axaml`, fondus et voiles en `#xx000000`) et iPhone (`Palette.bg`, `LaunchBackground`) : « noir total OLED », ogsas le 2026-11-12 ; gris du Mac et de l’iPhone neutres aussi) ; `Squircle` plat : fond uni et bord égal, plus de reflet ni de bord éclairé (dégradé jugé « horrible » par ogsas le 2026-11-04 ; `Depth` retiré) ; XAML par `{StaticResource}` (`Muted`, `Faint`, `FocusRing` en `DynamicResource` : contraste élevé), code par `Palette.Get("Nom")`. Jamais une couleur écrite, sauf dégradés, contenu (démo, affiches, marque) et animations ; `Dim` jamais pour du texte (test de contraste).
- Police Nunito auto-hébergée (la même partout, faite par `tools/fonts.py` : `pip install fonttools brotli` puis `python3 -I tools/fonts.py` ; pages de l'extension en WOFF2 ; le site : la police variable en sous-ensemble latin, `site/fonts/nunito.woff2`).
- Un test sans WPF va dans `tests/Mira.Core.Tests` (un fichier de Desktop sans WPF y est lié par son csproj) ; un test seulement Windows (chemins, liens physiques, DPAPI) dans `tests/Mira.Tests/Program.cs`. Code commun Windows/Mac dans Core (`IconPaths`, `MpvLists`, `MpvClient`, `PlaybackSession`, `SkipPlanner`) ; état du catalogue Windows dans `Catalog`, rangement TorLink dans `TorLinkPlacement`.

## Façon de travailler
- Changement visuel : maquettes d’abord (3 ou 4, dans `/mnt/project-files/<sujet>/`), ogsas choisit, puis le code ; un petit correctif visuel se fait directement.
- Windows est la référence, le Mac doit le suivre écran par écran. Windows se vérifie en vrai sur le Dell d’ogsas (Remote Control) après chaque lot fusionné ; Mac : CI et self-check sous Linux (`xvfb-run`) ; iPhone : simulateur d’`ios.yml`. Dis toujours ce qui n’a pas été essayé en vrai et note-le dans la décision.
- Une PR par sujet, fusionnée en rebase CI verte ; ogsas ne fait que ce qui exige son PC, son serveur ou son iPhone (publication comprise).

## Décisions fermées (ne pas rouvrir sans élément nouveau)
- Plateformes : Windows, Mac (Apple Silicon, pas d’Intel), iPhone ; pas d’Android ; Mira web retirée le 2026-11-05 (les pages `/Mira` de l’extension ne font que dire où prendre les apps).
- Publication non signée (`-Unsigned`) : SignPath Foundation a refusé le 2026-10-30 ; workflow et configurations gardés. Pas de Microsoft Store ni de MSIX. Faux positif de Defender : jamais d’exclusion comme remède.
- Pare-feu de Jellyfin limité aux réseaux privés, bouton « Passer en privé ». Lien public : Tailscale Funnel limité à `/Mira`, pas de Cloudflare Tunnel.
